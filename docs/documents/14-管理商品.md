## 一、模块概述

商品管理和分类管理是管理端的核心监管模块，负责全平台商品的查询、审核、下架、删除，以及商品分类的增删改查。管理员可以介入违规商品，保证市集内容合规。

### 1.1 模块职责

| 职责     | 说明                                                 |
| -------- | ---------------------------------------------------- |
| 商品列表 | 查询全平台商品，支持关键词、状态、审核状态、分类筛选 |
| 商品详情 | 查看商品完整信息，含图片、分类、卖家                 |
| 人工审核 | 对 pending 商品进行通过/拒绝                         |
| 强制下架 | 管理员介入下架违规商品                               |
| 删除商品 | 逻辑删除商品，物理删除图片                           |
| 分类列表 | 含禁用分类，供管理端使用                             |
| 新增分类 | 创建新的商品分类                                     |
| 修改分类 | 修改分类名、排序、状态                               |
| 删除分类 | 逻辑删除，有商品关联时拒绝                           |

### 1.2 模块边界

**做：**

- 全平台商品数据查询
- 商品审核、下架、删除
- 分类增删改查

**不做：**

- 用户端商品浏览、搜索、收藏（属于市集模块）
- 卖家自己发布、编辑、上下架（属于我的商店模块）
- 分类的用户端展示（属于市集模块）

### 1.3 与用户端市集模块的区别

| 对比       | 市集模块                | 管理端商品管理   |
| ---------- | ----------------------- | ---------------- |
| 数据范围   | 只看 approved + on_sale | 全部状态         |
| 核心操作   | 浏览、搜索、收藏        | 审核、下架、删除 |
| 路径       | /user/market/products   | /admin/products  |
| 权限       | 公开 / 登录用户         | 需管理员         |
| 分类可见性 | 只展示启用的分类        | 含禁用分类       |

### 2.2 商品列表

**流程：**

1. 接收查询条件（keyword、status、auditStatus、categoryId、分页）
2. 组装 SQL 条件：
   - keyword：模糊匹配 title
   - status：按上架状态筛选
   - auditStatus：按审核状态筛选
   - categoryId：按分类筛选
3. 分页查询 product 表（含所有状态，deleted = 0）
4. 关联查分类名、卖家昵称、封面图
5. 转 ProductVO
6. 返回 PageResult

**入参：**

| 参数        | 类型    | 必填 | 说明                          |
| ----------- | ------- | ---- | ----------------------------- |
| keyword     | String  | 否   | 关键词（标题），模糊匹配      |
| status      | String  | 否   | on_sale/reserved/sold/offline |
| auditStatus | String  | 否   | pending/approved/rejected     |
| categoryId  | Long    | 否   | 分类ID                        |
| pageNum     | Integer | 否   | 默认 1                        |
| pageSize    | Integer | 否   | 默认 10                       |

**返回：** Result<PageResult<ProductVO>>

### 2.3 商品详情

**流程：**

1. 校验商品存在
2. 查商品基本信息
3. 查商品图片列表
4. 查分类名
5. 查卖家信息（昵称、头像、信用分、认证状态、在售商品数）
6. 组装 ProductDetailVO
7. 返回

**返回：** Result<ProductDetailVO>

### 2.4 人工审核

**流程：**

1. 查商品，不存在报错
2. 校验商品当前审核状态是 pending
3. 校验审核结果合法（pass/reject）
4. 如果 pass：
   - 更新 audit_status = approved
   - 商品 status 保持 on_sale
   - 发站内信通知卖家
5. 如果 reject：
   - 更新 audit_status = rejected，记录 audit_reason
   - 商品 status 改为 offline
   - 发站内信通知卖家（含原因）
6. 返回

**入参：**

| 参数   | 类型   | 必填 | 约束          |
| ------ | ------ | ---- | ------------- |
| result | String | 是   | pass/reject   |
| reason | String | 否   | reject 时必填 |

**返回：** Result<Void>

**说明：** MVP 阶段商品发布直接 approved，所以这个接口暂时没有实际调用场景。但接口要先做好，后期接入 AI 审核后会用。

### 2.5 强制下架

**流程：**

1. 查商品，不存在报错
2. 更新 status = offline
3. 发站内信通知卖家（含原因）
4. 返回

**入参：**

| 参数   | 类型   | 必填 | 约束          |
| ------ | ------ | ---- | ------------- |
| reason | String | 否   | 最长 255 字符 |

**返回：** Result<Void>

### 2.6 删除商品

**流程：**

1. 查商品，不存在报错
2. 逻辑删除 product（deleted = 1）
3. 物理删除 product_image
4. 发站内信通知卖家
5. 返回

**返回：** Result<Void>

### 2.7 分类列表

**流程：**

1. 查所有分类（含禁用），deleted = 0
2. 按 sort 升序、id 升序
3. 转 CategoryVO
4. 返回

**返回：** Result<List<CategoryVO>>

### 2.8 新增分类

**流程：**

1. 生成雪花 ID
2. 构造 Category（默认 parentId=0、sort=0、status=1）
3. 插入 category
4. 返回分类 ID

**入参：**

| 参数     | 类型    | 必填 | 约束         |
| -------- | ------- | ---- | ------------ |
| name     | String  | 是   | 最长 50 字符 |
| parentId | Long    | 否   | 默认 0       |
| sort     | Integer | 否   | 默认 0       |
| status   | Integer | 否   | 默认 1       |

**返回：** Result<Long>

### 2.9 修改分类

**流程：**

1. 查分类，不存在报错
2. 更新分类（name、parentId、sort、status 按需更新）
3. 返回

**返回：** Result<Void>

### 2.10 删除分类

**流程：**

1. 查分类，不存在报错
2. 检查该分类下是否有商品：
   - 有 → 报错"该分类下有 N 个商品，无法删除"
   - 无 → 逻辑删除
3. 返回

**返回：** Result<Void>

## 三、数据库设计

**复用市集模块已建的表，不新增表。**

### 3.1 product 表

```sql
CREATE TABLE IF NOT EXISTS `product` (
    `id`             BIGINT        NOT NULL COMMENT '主键',
    `seller_id`      BIGINT        NOT NULL COMMENT '卖家ID',
    `category_id`    BIGINT        NOT NULL COMMENT '分类ID',
    `title`          VARCHAR(100)  NOT NULL COMMENT '标题',
    `description`    TEXT          COMMENT '描述',
    `price`          DECIMAL(10,2) NOT NULL COMMENT '售价',
    `original_price` DECIMAL(10,2) DEFAULT NULL COMMENT '原价',
    `quality`        VARCHAR(20)   NOT NULL DEFAULT 'good' COMMENT '成色',
    `trade_type`     VARCHAR(20)   NOT NULL DEFAULT 'face' COMMENT '交易方式',
    `trade_place`    VARCHAR(100)  DEFAULT NULL COMMENT '交易地点',
    `status`         VARCHAR(20)   NOT NULL DEFAULT 'on_sale' COMMENT '上架状态',
    `audit_status`   VARCHAR(20)   NOT NULL DEFAULT 'pending' COMMENT '审核状态',
    `audit_reason`   VARCHAR(255)  DEFAULT NULL COMMENT '审核拒绝原因',
    `view_count`     INT           NOT NULL DEFAULT 0 COMMENT '浏览量',
    `favorite_count` INT           NOT NULL DEFAULT 0 COMMENT '收藏数',
    `create_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`        TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_seller_id` (`seller_id`),
    KEY `idx_category_id` (`category_id`),
    KEY `idx_status` (`status`),
    KEY `idx_audit_status` (`audit_status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品表';
```

### 3.2 product_image 表

```sql
CREATE TABLE IF NOT EXISTS `product_image` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `product_id`  BIGINT       NOT NULL COMMENT '商品ID',
    `url`         VARCHAR(500) NOT NULL COMMENT '图片URL',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序，0为封面',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_product_id` (`product_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品图片表';
```

### 3.3 category 表

```sql
CREATE TABLE IF NOT EXISTS `category` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `name`        VARCHAR(50)  NOT NULL COMMENT '分类名',
    `parent_id`   BIGINT       NOT NULL DEFAULT 0 COMMENT '父分类ID，0表示一级分类',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态 1启用 0禁用',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_parent_id` (`parent_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品分类表';
```

### 3.4 表关系

```
category 1---N product
product  1---N product_image
user     1---N product
```

## 五、安全设计

### 5.1 权限隔离

管理端接口在 `/admin/**` 下：

- 用户 token 不能访问（type 校验）
- 只有管理员 token 能访问
- 拦截器校验 `type = admin`

### 5.2 操作权限

MVP 阶段，所有管理员都能操作商品和分类管理功能。

**后续优化：** 按角色细分：

| 角色        | 权限                         |
| ----------- | ---------------------------- |
| SUPER_ADMIN | 全部                         |
| ADMIN       | 商品管理、用户管理、订单管理 |
| AUDITOR     | 只能审核认证、商品           |
| OPERATOR    | 只能查看，不能修改           |

### 5.3 关键操作留痕

| 操作     | 留痕                                 |
| -------- | ------------------------------------ |
| 人工审核 | 写入 audit_status、audit_reason      |
| 强制下架 | 发站内信通知卖家（含原因）           |
| 删除商品 | 逻辑删除，发站内信通知卖家           |
| 删除分类 | 有商品关联时拒绝，避免破坏数据完整性 |

**后续优化：** 加管理员操作日志表，记录每次管理操作的 IP、时间、目标。

### 5.4 防止误操作

| 保护         | 说明                           |
| ------------ | ------------------------------ |
| 审核状态校验 | 只能审核 pending 商品，防重复  |
| 删除分类校验 | 有商品关联时拒绝删除           |
| 逻辑删除     | 商品、分类都用逻辑删除，可追溯 |

## 十、设计决策记录

| 决策                | 选择                                       | 原因                               |
| ------------------- | ------------------------------------------ | ---------------------------------- |
| 复用 product 表     | 不新增表                                   | 数据结构与用户端一致               |
| 复用 CategoryMapper | 追加 SQL                                   | 减少重复代码                       |
| 人工审核            | 只允许审核 pending                         | 防重复审核                         |
| 审核拒绝            | audit_status = rejected + status = offline | 商品同时下架，避免违规内容继续展示 |
| 强制下架            | 只改 status，不改 audit_status             | 保留审核历史                       |
| 删除商品            | product 逻辑删 + image 物理删              | 图片表无 deleted 字段              |
| 删除分类            | 有商品关联时拒绝                           | 保护数据完整性                     |
| 分类列表            | 含禁用分类                                 | 管理端需要看到全部                 |
| 通知机制            | 复用 MessageSender                         | 解耦，统一消息入口                 |
| 权限                | MVP 不细分角色                             | 后期按角色控制                     |
