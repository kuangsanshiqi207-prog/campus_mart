# 文件存储模块设计文档

> 模块：文件存储
> 版本：V1.0
> 更新日期：2026-09-23

---

## 一、模块概述

文件存储模块负责统一管理所有文件上传，是商品、认证、评价等模块的基础能力。通过抽象存储接口，支持后期自由切换存储后端（阿里云 OSS / 本地磁盘 / MinIO）。

### 1.1 模块职责

| 职责         | 说明                                       |
| ------------ | ------------------------------------------ |
| 文件上传     | 接收文件，校验后存储，返回 URL             |
| 文件归属记录 | 记录每个文件由谁上传，用于越权校验         |
| 文件使用标记 | 标记文件被业务引用，便于后期清理未使用文件 |
| 存储后端切换 | 通过配置切换 OSS / 本地，业务代码不感知    |

### 1.2 模块边界

**做：**

- 文件上传、归属管理
- 存储后端抽象与切换

**不做：**

- 图片压缩、裁剪
- 图片水印
- 文件内容审核（属于 AI 审核模块）

## 二、架构设计

### 2.1 分层结构

```text
Controller          FileController
                     ↓
Service             FileService（业务层：校验、命名、写 file 表）
                     ↓
StorageService      FileStorageService（存储层：只管存取）
                     ↓
实现类              AliOssFileStorageService / LocalFileStorageService
```

### 2.2 分层职责

| 层                 | 职责                                                 |
| ------------------ | ---------------------------------------------------- |
| FileController     | 接收请求、参数校验                                   |
| FileService        | 文件类型/大小校验、生成文件名、写 file 表、标记 used |
| FileStorageService | 上传字节流到具体存储、返回 URL                       |
| 实现类             | OSS 上传 / 本地磁盘保存                              |

### 2.3 存储后端切换

通过配置 `campus.file.storage-type` 切换：

```yaml
campus:
  file:
    storage-type: aliyun-oss    # aliyun-oss / local
```

实现类通过 `@ConditionalOnProperty` 二选一：

```java
@Service
@ConditionalOnProperty(name = "campus.file.storage-type", havingValue = "aliyun-oss")
public class AliOssFileStorageService implements FileStorageService { ... }

@Service
@ConditionalOnProperty(name = "campus.file.storage-type", havingValue = "local")
public class LocalFileStorageService implements FileStorageService { ... }
```

**业务代码只注入 `FileStorageService`，不关心具体实现。**

## 三、功能设计

### 3.1 功能清单

| 编号 | 功能     | 接口                    | 是否需登录 |
| ---- | -------- | ----------------------- | ---------- |
| F1   | 上传文件 | POST /user/files/upload | 是         |

### 3.2 上传文件

**流程：**

1. 拦截器校验 token，注入 userId
2. 校验文件非空
3. 校验文件大小 ≤ 5MB
4. 校验扩展名（jpg/jpeg/png/gif/webp）
5. 生成文件名：`{yyyyMMdd}/{雪花ID}.{扩展名}`
6. 调用 FileStorageService.upload 存储
7. 写 file 表，status = unused
8. 返回 { fileId, url, name, size }

**入参：**

| 参数 | 类型          | 必填 | 说明            |
| ---- | ------------- | ---- | --------------- |
| file | MultipartFile | 是   | 表单字段名 file |

**返回：** Result<FileVO>

| 字段   | 类型   | 说明                     |
| ------ | ------ | ------------------------ |
| fileId | Long   | 文件ID，用于后续业务提交 |
| url    | String | 访问URL，用于前端预览    |
| name   | String | 原始文件名               |
| size   | Long   | 文件大小（字节）         |

### 3.3 业务方如何使用

业务方（商品、认证等）**接收 fileId，不接收 URL**：

```text
前端流程：
  1. 上传图片 → 拿到 fileId
  2. 用 fileId 提交业务接口

后端流程：
  1. 接收 fileId
  2. 调 fileService.getFileOwnedByUser(fileId, userId) 校验归属
  3. 取出 url 存到业务表
  4. 调 fileService.markUsed(fileId) 标记已使用
```

**为什么用 fileId 不用 URL：**

- 后端能校验文件归属，防止 A 用户冒用 B 用户的图片
- 前端传 URL 无法验证

## 四、数据库设计

### 4.1 file 表

```sql
CREATE TABLE IF NOT EXISTS `file` (
    `id`            BIGINT       NOT NULL COMMENT '主键',
    `user_id`       BIGINT       NOT NULL COMMENT '上传者ID',
    `url`           VARCHAR(500) NOT NULL COMMENT '访问URL',
    `original_name` VARCHAR(255) DEFAULT NULL COMMENT '原始文件名',
    `file_size`     BIGINT       DEFAULT NULL COMMENT '文件大小(字节)',
    `content_type`  VARCHAR(100) DEFAULT NULL COMMENT 'MIME类型',
    `status`        VARCHAR(20)  NOT NULL DEFAULT 'unused' COMMENT '状态 unused/used',
    `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`       TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_status` (`status`),
    KEY `idx_create_time` (`create_time`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '文件记录表';
```

### 4.2 字段说明

| 字段          | 说明               | 约束        |
| ------------- | ------------------ | ----------- |
| id            | 主键，雪花算法生成 | 唯一        |
| user_id       | 上传者ID           | 非空        |
| url           | 访问URL            | 非空        |
| original_name | 原始文件名         | 可空        |
| file_size     | 文件大小           | 可空        |
| content_type  | MIME类型           | 可空        |
| status        | unused / used      | 默认 unused |
| deleted       | 逻辑删除           | 默认 0      |

### 4.3 status 用途

| 值     | 含义             | 后期处理   |
| ------ | ---------------- | ---------- |
| unused | 刚上传，未被引用 | N 天后清理 |
| used   | 已被业务引用     | 保留       |

**MVP 阶段只记录状态，不做清理。后期加定时任务删除 unused 文件。**

## 五、存储配置

### 5.1 存储类型

| 类型       | 值         | 用途           |
| ---------- | ---------- | -------------- |
| 阿里云 OSS | aliyun-oss | 生产环境       |
| 本地磁盘   | local      | 开发测试、备用 |

### 5.2 application-dev.yml 配置

```yaml
campus:
  file:
    storage-type: aliyun-oss
    local:
      base-path: ./uploads
      base-url: http://localhost:8080/uploads

alioss:
  endpoint: oss-cn-hangzhou.aliyuncs.com
  access-key-id: your-access-key-id
  access-key-secret: your-access-key-secret
  bucket-name: your-bucket-name
```

### 5.3 本地存储的静态资源映射

`WebMvcConfiguration` 里注册：

```java
@Override
public void addResourceHandlers(ResourceHandlerRegistry registry) {
    String basePath = fileProperties.getLocal().getBasePath();
    registry.addResourceHandler("/uploads/**")
            .addResourceLocations("file:" + System.getProperty("user.dir") + "/" + basePath + "/");
}
```

这样 `http://localhost:8080/uploads/20260923/xxx.jpg` 就能访问本地保存的图片。

## 六、安全设计

### 6.1 上传接口需要登录

`/user/files/upload` 不放在拦截器放行列表，未登录访问返回 401。

**原因：** 防止匿名用户恶意刷空间。

### 6.2 文件大小限制

单文件最大 5MB。

**前端：** 也可以在选文件时限制。
**后端：** `FileService` 里二次校验。

### 6.3 文件类型限制

只允许 `jpg / jpeg / png / gif / webp`。

**通过扩展名校验**（不只看 Content-Type，因为 Content-Type 可以伪造）。

### 6.4 归属校验

业务方调 `fileService.getFileOwnedByUser(fileId, userId)` 时：

- 查 file 表
- 校验 `file.userId == 当前 userId`
- 不匹配抛异常

**防止 A 用户冒用 B 用户的图片。**

### 6.5 文件名安全

生成的文件名用**雪花 ID**，不用原始文件名：

```text
{yyyyMMdd}/{雪花ID}.{扩展名}
```

**好处：**

- 避免文件名冲突
- 避免用户传入恶意路径 `../../etc/passwd`
- 避免泄露原始文件名

## 七、异常处理

### 7.1 业务异常

| 场景         | 异常信息                                    |
| ------------ | ------------------------------------------- |
| 文件为空     | 文件不能为空                                |
| 文件超过 5MB | 文件大小不能超过 5MB                        |
| 扩展名不允许 | 只允许上传 jpg/jpeg/png/gif/webp 格式的图片 |
| 文件不存在   | 文件不存在                                  |
| 文件归属不对 | 无权使用该文件                              |

## 十一、设计决策记录

| 决策             | 选择                   | 原因                     |
| ---------------- | ---------------------- | ------------------------ |
| 存储抽象         | 接口 + 多实现          | 后期切换存储不改业务代码 |
| 存储切换         | @ConditionalOnProperty | 配置驱动，零代码改动     |
| 业务传 fileId    | 不传 URL               | 后端可校验归属，防冒用   |
| 上传接口返回 url | 返回                   | 前端预览用               |
| 文件名生成       | 雪花 ID + 日期目录     | 避免冲突、泄露原文件名   |
| 文件大小限制     | 5MB                    | 校园场景足够             |
| 文件类型校验     | 扩展名                 | Content-Type 可伪造      |
| status 字段      | unused / used          | 后期清理未引用文件       |
| 上传接口需登录   | 是                     | 防匿名刷空间             |
| 本地存储静态映射 | WebMvcConfigurer       | 支持 local 模式访问      |
