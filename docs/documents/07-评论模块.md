## 一、模块概述

评价模块负责交易完成后的买卖互评，是信用体系的基础。买卖双方在订单完成后可以互相评价，被评价人可以回复。

### 1.1 模块职责

| 职责         | 说明                     |
| ------------ | ------------------------ |
| 发表评价     | 订单完成后，买卖双方互评 |
| 回复评价     | 被评价人对评价进行回复   |
| 商品评价列表 | 查看某商品的所有评价     |
| 我的评价     | 查看我发出的评价         |
| 我收到的评价 | 查看我收到的评价         |
| 评价详情     | 查看单条评价完整信息     |

### 1.2 模块边界

**做：**

- 评价的创建、回复
- 评价的查询
- 图片附件（通过 fileId 引用）

**不做：**

- 信用分计算（属于个人统计模块）
- 评价审核（属于管理端评价管理）
- 评价统计（属于个人统计模块）

### 1.3 评价关系

```
订单完成
    ↓
买家评价卖家 ─── 5 星好评
卖家评价买家 ─── 5 星好评
    ↓
被评价人可以回复一次
```

**双向评价，各自独立。**

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能         | 接口                                  | 是否需登录 |
| ---- | ------------ | ------------------------------------- | ---------- |
| F1   | 发表评价     | POST /user/reviews                    | 是         |
| F2   | 我发出的评价 | GET /user/reviews/mine                | 是         |
| F3   | 我收到的评价 | GET /user/reviews/received            | 是         |
| F4   | 商品评价列表 | GET /user/reviews/product/{productId} | 否         |
| F5   | 评价详情     | GET /user/reviews/detail/{id}         | 否         |
| F6   | 回复评价     | POST /user/reviews/{id}/reply         | 是         |

### 2.2 发表评价

**流程：**

1. 从 BaseContext 取 userId
2. 查订单，不存在报错
3. 校验 userId 是买家或卖家
4. 校验订单状态是 completed
5. 校验是否已评价过（`orderId + fromUserId` 唯一）
6. 确定被评价人 `toUserId`
7. 处理图片文件（校验归属、标记 used）
8. 插入 review 记录
9. 返回评价 ID

**入参：**

| 参数         | 类型       | 必填 | 约束          |
| ------------ | ---------- | ---- | ------------- |
| orderId      | Long       | 是   | 订单ID        |
| score        | Integer    | 是   | 1-5           |
| content      | String     | 否   | 最长 500 字符 |
| imageFileIds | List<Long> | 否   | 最多 9 张     |

**返回：** Result<Long>（评价 ID）

### 2.3 回复评价

**流程：**

1. 从 BaseContext 取 userId
2. 查评价，不存在报错
3. 校验 userId 是被评价人
4. 校验未回复过
5. 更新 reply 和 reply_time
6. 返回成功

**入参：**

| 参数    | 类型   | 必填 | 约束          |
| ------- | ------ | ---- | ------------- |
| content | String | 是   | 最长 500 字符 |

**返回：** Result<Void>

### 2.4 商品评价列表

**流程：**

1. 按 productId 查评价
2. 按创建时间倒序
3. 关联查商品标题、评价人昵称头像
4. 分页返回

**入参：**

| 参数      | 类型    | 必填 | 说明    |
| --------- | ------- | ---- | ------- |
| productId | Long    | 是   | 商品ID  |
| pageNum   | Integer | 否   | 默认 1  |
| pageSize  | Integer | 否   | 默认 10 |

**返回：** Result<PageResult>

### 2.5 我发出的评价

**流程：**

1. 从 BaseContext 取 userId
2. 按 fromUserId 查评价
3. 按创建时间倒序
4. 分页返回

### 2.6 我收到的评价

**流程：**

1. 从 BaseContext 取 userId
2. 按 toUserId 查评价
3. 按创建时间倒序
4. 分页返回

### 2.7 评价详情

**流程：**

1. 按 id 查评价
2. 不存在报错
3. 返回完整信息

## 三、数据库设计

### 3.1 review 表

```sql
CREATE TABLE IF NOT EXISTS `review` (
    `id`             BIGINT        NOT NULL COMMENT '主键',
    `order_id`       BIGINT        NOT NULL COMMENT '订单ID',
    `product_id`     BIGINT        NOT NULL COMMENT '商品ID',
    `from_user_id`   BIGINT        NOT NULL COMMENT '评价人ID',
    `to_user_id`     BIGINT        NOT NULL COMMENT '被评价人ID',
    `score`          TINYINT       NOT NULL COMMENT '评分 1-5',
    `content`        VARCHAR(500)  DEFAULT NULL COMMENT '评价内容',
    `images`         VARCHAR(2000) DEFAULT NULL COMMENT '图片URL列表，逗号分隔',
    `reply`          VARCHAR(500)  DEFAULT NULL COMMENT '被评价人的回复',
    `reply_time`     DATETIME      DEFAULT NULL COMMENT '回复时间',
    `create_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`        TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_order_from` (`order_id`, `from_user_id`),
    KEY `idx_product_id` (`product_id`),
    KEY `idx_to_user_id` (`to_user_id`),
    KEY `idx_from_user_id` (`from_user_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '评价表';
```

### 3.2 字段说明

| 字段         | 说明               | 约束             |
| ------------ | ------------------ | ---------------- |
| id           | 主键，雪花算法生成 | 唯一             |
| order_id     | 订单ID             | 关联 order.id    |
| product_id   | 商品ID             | 关联 product.id  |
| from_user_id | 评价人ID           | 关联 user.id     |
| to_user_id   | 被评价人ID         | 关联 user.id     |
| score        | 评分               | 1-5              |
| content      | 评价内容           | 最长 500         |
| images       | 图片URL列表        | 逗号分隔的字符串 |
| reply        | 回复内容           | 最长 500         |
| reply_time   | 回复时间           | -                |

### 3.3 关键索引

**唯一索引 `uk_order_from`：**

```sql
UNIQUE KEY `uk_order_from` (`order_id`, `from_user_id`)
```

**作用：** 保证一个订单中，同一个评价人只能评价一次。

- 买家评价卖家：`(订单1, 买家1)` 唯一
- 卖家评价买家：`(订单1, 卖家1)` 唯一
- 两者不冲突

**普通索引：**

- `idx_product_id`：商品评价列表查询
- `idx_to_user_id`：我收到的评价
- `idx_from_user_id`：我发出的评价

### 3.4 表关系

```
order   1---N review
product 1---N review
user    1---N review (作为评价人)
user    1---N review (作为被评价人)
```

## 四、图片存储设计

### 4.1 存储方式

`review.images` 是 `VARCHAR(2000)`，存**逗号分隔的 URL 字符串**：

```
https://oss.xxx.com/a.jpg,https://oss.xxx.com/b.jpg,https://oss.xxx.com/c.jpg
```

### 4.2 Java 侧的处理

| 位置                   | 类型                |
| ---------------------- | ------------------- |
| 数据库                 | VARCHAR（逗号分隔） |
| Entity `Review.images` | String              |
| VO `ReviewVO.images`   | List<String>        |

**写入：** Service 里把 List 拼成 String

```java
String imagesStr = String.join(",", urls);
```

**读取：** 通过 MyBatis TypeHandler 自动转

### 4.3 自定义 TypeHandler

**位置：** `mart-server/src/main/java/com/example/handler/CommaSeparatedStringListTypeHandler.java`

```java
@MappedTypes(List.class)
public class CommaSeparatedStringListTypeHandler extends BaseTypeHandler<List<String>> {
    // 写入：List<String> → String
    // 读取：String → List<String>
}
```

**Mapper XML 里指定：**

```xml
<resultMap id="ReviewVOMap" type="com.example.vo.review.ReviewVO">
    <!-- ... 其他字段 ... -->
    <result property="images" column="images"
            typeHandler="com.example.handler.CommaSeparatedStringListTypeHandler"/>
</resultMap>
```

### 4.4 为什么不独立建 review_image 表

| 方案     | 优点           | 缺点                 |
| -------- | -------------- | -------------------- |
| 独立表   | 规范化，可查询 | 多一次查询，代码复杂 |
| 逗号分隔 | 简单，一次查询 | 无法按图片查询       |

**评价图片仅用于展示，不参与查询和统计**，逗号分隔足够。MVP 阶段选择简单方案。

## 五、安全设计

### 5.1 评价权限校验

| 校验项       | 说明                            |
| ------------ | ------------------------------- |
| 订单存在     | 不存在报错                      |
| 是订单参与方 | 只有买卖双方能评价              |
| 订单已完成   | pending/accepted 等状态不能评价 |
| 未重复评价   | 用唯一索引 + 查询双重保证       |

### 5.2 回复权限校验

| 校验项     | 说明                 |
| ---------- | -------------------- |
| 评价存在   | 不存在报错           |
| 是被评价人 | 只有被评价人能回复   |
| 未回复过   | 一条评价只能回复一次 |

### 5.3 图片归属校验

通过 `fileService.getFileOwnedByUser(fileId, userId)` 校验：

```
1. 查 file 表
2. 判断 file.userId == 当前 userId
   ├─ 匹配 → 继续
   └─ 不匹配 → 报错"无权使用该文件"
```

**防止用户 A 冒用用户 B 上传的图片。**

### 5.4 公开访问范围

| 接口         | 是否公开 |
| ------------ | -------- |
| 商品评价列表 | ✅ 公开   |
| 评价详情     | ✅ 公开   |
| 我发出的评价 | ❌ 需登录 |
| 我收到的评价 | ❌ 需登录 |
| 发表评价     | ❌ 需登录 |
| 回复评价     | ❌ 需登录 |

**公开接口放行：** `/user/reviews/product/**` 和 `/user/reviews/detail/**`

## 十、设计决策记录

| 决策         | 选择                     | 原因               |
| ------------ | ------------------------ | ------------------ |
| 评价触发     | 订单完成后               | 保证交易真实性     |
| 评价方向     | 双向互评                 | 买卖双方都有评价权 |
| 唯一性约束   | (order_id, from_user_id) | 一人一单一评       |
| 图片存储     | 逗号分隔的 VARCHAR       | 简单，仅展示       |
| 图片类型转换 | 自定义 TypeHandler       | 自动 String↔List   |
| 回复限制     | 一条评价只能回复一次     | 防止刷屏           |
| 评价详情路径 | /detail/{id}             | 避免路径冲突       |
| 公开范围     | 商品评价列表 + 详情公开  | 匿名用户可看       |
| 越权校验     | 订单参与方 + 文件归属    | 防止数据泄露       |
| 评价删除     | 逻辑删除                 | 保留历史数据       |
