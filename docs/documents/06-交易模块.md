## 一、模块概述

交易模块是用户端的核心业务模块，负责买卖双方的交易撮合。买家发起申请，卖家确认后完成线下面交。买卖合一，同一用户在不同订单中可分别作为买家或卖家。

### 1.1 模块职责

| 职责     | 说明                           |
| -------- | ------------------------------ |
| 申请交易 | 买家对商品发起交易申请         |
| 接受交易 | 卖家接受买家的申请             |
| 拒绝交易 | 卖家拒绝买家的申请             |
| 取消订单 | 双方可取消待处理或待交易的订单 |
| 确认完成 | 买家确认交易完成               |
| 订单列表 | 按视角查看我买到的/我卖出的    |
| 订单详情 | 查看订单完整信息               |

### 1.2 模块边界

**做：**

- 交易的创建、状态流转
- 订单查询
- 商品状态联动

**不做：**

- 支付（校园场景线下面交）
- 物流（面交为主）
- 评价（属于评价模块）
- 退款（MVP 阶段不做）

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能         | 接口                           | 是否需登录 |
| ---- | ------------ | ------------------------------ | ---------- |
| F1   | 申请交易     | POST /user/orders              | 是         |
| F2   | 订单列表     | GET /user/orders               | 是         |
| F3   | 订单详情     | GET /user/orders/{id}          | 是         |
| F4   | 卖家接受     | PUT /user/orders/{id}/accept   | 是         |
| F5   | 卖家拒绝     | PUT /user/orders/{id}/reject   | 是         |
| F6   | 取消订单     | PUT /user/orders/{id}/cancel   | 是         |
| F7   | 买家确认完成 | PUT /user/orders/{id}/complete | 是         |

### 2.2 申请交易

**流程：**

1. 从 BaseContext 取 userId
2. 查商品，校验存在、审核通过、在售
3. 校验买家不是卖家本人
4. 检查商品是否已有待处理订单
5. 生成雪花 ID 和订单号
6. 构造 Order，status = pending
7. 插入订单
8. 返回订单 ID

**入参：**

| 参数            | 类型     | 必填 | 说明               |
| --------------- | -------- | ---- | ------------------ |
| productId       | Long     | 是   | 商品ID             |
| remark          | String   | 否   | 买家留言，最长 500 |
| tradePlace      | String   | 否   | 期望交易地点       |
| appointmentTime | DateTime | 否   | 期望交易时间       |

**返回：** Result<Long>（订单 ID）

### 2.3 卖家接受

**流程：**

1. 从 BaseContext 取 userId
2. 查订单，校验 sellerId 匹配
3. 校验状态是 pending
4. 更新订单状态 accepted
5. 更新商品状态 reserved

**返回：** Result<Void>

### 2.4 卖家拒绝

**流程：**

1. 从 BaseContext 取 userId
2. 查订单，校验 sellerId 匹配
3. 校验状态是 pending
4. 更新订单状态 rejected，记录拒绝原因

**返回：** Result<Void>

### 2.5 取消订单

**流程：**

1. 从 BaseContext 取 userId
2. 查订单，校验 userId 是买家或卖家
3. 校验状态是 pending 或 accepted
4. 更新订单状态 cancelled，记录取消原因
5. 商品状态恢复 on_sale

**返回：** Result<Void>

### 2.6 买家确认完成

**流程：**

1. 从 BaseContext 取 userId
2. 查订单，校验 buyerId 匹配
3. 校验状态是 accepted
4. 更新订单状态 completed，记录完成时间
5. 商品状态改为 sold

**返回：** Result<Void>

### 2.7 订单列表

**流程：**

1. 从 BaseContext 取 userId
2. 根据 type 判断视角：
   - buy：查 buyerId = userId
   - sell：查 sellerId = userId
3. 可选按 status 筛选
4. 关联查商品信息、买卖双方昵称
5. 按创建时间倒序
6. 分页返回

**入参：**

| 参数     | 类型    | 必填 | 说明       |
| -------- | ------- | ---- | ---------- |
| type     | String  | 是   | buy / sell |
| status   | String  | 否   | 状态筛选   |
| pageNum  | Integer | 否   | 默认 1     |
| pageSize | Integer | 否   | 默认 10    |

### 2.8 订单详情

**流程：**

1. 从 BaseContext 取 userId
2. 查订单，校验 userId 是买家或卖家
3. 返回完整信息

## 三、订单状态机

### 3.1 状态定义

| 状态      | 含义               |
| --------- | ------------------ |
| pending   | 待卖家确认         |
| accepted  | 卖家已接受，待交易 |
| rejected  | 卖家已拒绝         |
| completed | 已完成             |
| cancelled | 已取消             |

### 3.2 状态流转图

```
pending ──卖家接受──→ accepted ──买家完成──→ completed
   │                    │
   │                    │
   ├──卖家拒绝──→ rejected
   │
   └──双方取消──→ cancelled

accepted ──双方取消──→ cancelled
```

### 3.3 状态操作矩阵

| 当前状态  | 卖家接受 | 卖家拒绝 | 取消 | 买家完成 |
| --------- | -------- | -------- | ---- | -------- |
| pending   | ✅        | ✅        | ✅    | ❌        |
| accepted  | ❌        | ❌        | ✅    | ✅        |
| rejected  | ❌        | ❌        | ❌    | ❌        |
| completed | ❌        | ❌        | ❌    | ❌        |
| cancelled | ❌        | ❌        | ❌    | ❌        |

### 3.4 商品状态联动

| 订单事件 | 商品状态变化       |
| -------- | ------------------ |
| 卖家接受 | on_sale → reserved |
| 取消订单 | reserved → on_sale |
| 买家完成 | reserved → sold    |
| 卖家拒绝 | 不变               |

## 四、数据库设计

### 4.1 order 表

```sql
CREATE TABLE IF NOT EXISTS `order` (
    `id`               BIGINT        NOT NULL COMMENT '主键',
    `order_no`         VARCHAR(32)   NOT NULL COMMENT '订单号',
    `product_id`       BIGINT        NOT NULL COMMENT '商品ID',
    `buyer_id`         BIGINT        NOT NULL COMMENT '买家ID',
    `seller_id`        BIGINT        NOT NULL COMMENT '卖家ID',
    `amount`           DECIMAL(10,2) NOT NULL COMMENT '成交金额',
    `status`           VARCHAR(20)   NOT NULL DEFAULT 'pending' COMMENT '订单状态',
    `trade_type`       VARCHAR(20)   DEFAULT NULL COMMENT '交易方式',
    `trade_place`      VARCHAR(100)  DEFAULT NULL COMMENT '交易地点',
    `appointment_time` DATETIME      DEFAULT NULL COMMENT '约定时间',
    `remark`           VARCHAR(500)  DEFAULT NULL COMMENT '买家留言',
    `reject_reason`    VARCHAR(255)  DEFAULT NULL COMMENT '卖家拒绝原因',
    `cancel_reason`    VARCHAR(255)  DEFAULT NULL COMMENT '取消原因',
    `create_time`      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `completed_time`   DATETIME      DEFAULT NULL COMMENT '完成时间',
    `deleted`          TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_order_no` (`order_no`),
    KEY `idx_buyer_id` (`buyer_id`),
    KEY `idx_seller_id` (`seller_id`),
    KEY `idx_product_id` (`product_id`),
    KEY `idx_status` (`status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '订单表';
```

### 4.2 字段说明

| 字段             | 说明               | 约束                                          |
| ---------------- | ------------------ | --------------------------------------------- |
| id               | 主键，雪花算法生成 | 唯一                                          |
| order_no         | 订单号，用于展示   | 唯一，格式：时间戳+随机                       |
| product_id       | 商品ID             | 关联 product.id                               |
| buyer_id         | 买家ID             | 关联 user.id                                  |
| seller_id        | 卖家ID             | 关联 user.id                                  |
| amount           | 成交金额           | 快照，商品改价不影响                          |
| status           | 订单状态           | pending/accepted/rejected/completed/cancelled |
| trade_type       | 交易方式           | 从商品快照                                    |
| trade_place      | 交易地点           | 买家的期望地点                                |
| appointment_time | 约定时间           | 买家填写的期望时间                            |
| remark           | 买家留言           | 最长 500                                      |
| reject_reason    | 拒绝原因           | 卖家拒绝时填                                  |
| cancel_reason    | 取消原因           | 双方取消时填                                  |
| completed_time   | 完成时间           | 完成时记录                                    |

### 4.3 表关系

```
user    1---N order (作为买家)
user    1---N order (作为卖家)
product 1---N order
```

## 五、订单号设计

### 5.1 格式

```
yyyyMMddHHmmss + 6 位随机数
```

示例：`20260924153045123456`

- 前 14 位：时间戳
- 后 6 位：随机数

### 5.2 为什么用时间戳+随机数

| 方案            | 优点                 | 缺点         |
| --------------- | -------------------- | ------------ |
| 自增 ID         | 简单                 | 暴露订单量   |
| UUID            | 全局唯一             | 无序、难读   |
| 雪花 ID         | 有序、唯一           | 太长         |
| **时间戳+随机** | 可读、有序、不暴露量 | 极小概率重复 |

**依赖唯一索引兜底**，极小概率冲突时插入失败重试。

## 六、安全设计

### 6.1 越权防护

每个操作都校验当前用户与订单的关系：

| 操作 | 校验                          |
| ---- | ----------------------------- |
| 接受 | userId == sellerId            |
| 拒绝 | userId == sellerId            |
| 取消 | userId == buyerId 或 sellerId |
| 完成 | userId == buyerId             |
| 详情 | userId == buyerId 或 sellerId |

### 6.2 重复下单防护

同一商品不允许同时存在多个 pending/accepted 订单：

```sql
SELECT * FROM order
WHERE product_id = ?
  AND status IN ('pending', 'accepted')
  AND deleted = 0
LIMIT 1
```

有则拒绝新申请。

### 6.3 商品状态校验

申请交易时商品必须：

- audit_status = approved
- status = on_sale

防止用户对已下架/已售出商品下单。

### 6.4 金额快照

订单的 `amount` 是**下单时的价格快照**，商品后续改价不影响已有订单。

## 十一、设计决策记录

| 决策           | 选择                     | 原因                   |
| -------------- | ------------------------ | ---------------------- |
| 订单号生成     | 时间戳+随机数            | 可读、有序、不暴露量   |
| 商品状态联动   | 接受→reserved，完成→sold | 保证商品不被重复售出   |
| 金额快照       | 存到订单表               | 商品改价不影响历史订单 |
| 重复下单防护   | 查 pending/accepted      | 防止一物多卖           |
| 取消后商品状态 | 恢复 on_sale             | 让商品重新可售         |
| 拒绝后商品状态 | 不变（仍 on_sale）       | 其他买家还能买         |
| 订单删除       | 逻辑删除                 | 保留历史记录           |
| 订单查看权限   | 只有买卖双方             | 保护隐私               |
| MVP 不做退款   | 线下面交                 | 无线上支付             |
