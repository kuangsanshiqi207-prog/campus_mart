# 举报模块设计文档

> 模块：举报
> 版本：V1.0
> 更新日期：2026-09-24

---

## 一、模块概述

举报模块负责处理用户对商品、用户、订单的违规举报，以及被举报人的申诉。举报由用户发起，由管理端处理，是平台内容治理和违规打击的重要环节。

### 1.1 模块职责

| 职责     | 说明                                   |
| -------- | -------------------------------------- |
| 提交举报 | 用户对商品/用户/订单发起举报，上传证据 |
| 我的举报 | 查看自己提交的举报记录                 |
| 举报详情 | 查看举报处理进度                       |
| 提交申诉 | 被举报人对处理结果申诉                 |

### 1.2 模块边界

**做：**

- 举报的创建、查询
- 申诉的提交
- 举报与申诉的图片附件（通过 fileId 引用）

**不做：**

- 举报的处理（属于管理端举报管理）
- 申诉的处理（属于管理端举报管理）
- 自动处罚（由管理员根据举报结果手动执行）

### 1.3 举报与申诉的关系

```
用户 A 举报商品 X
    ↓
管理员处理 → 举报成立（valid）
    ↓
商品 X 的卖家（被举报人）可以申诉
    ↓
管理员处理申诉 → 通过（撤销处罚）/ 驳回（维持处罚）
```

**举报 → 处理 → 申诉 → 处理** 是完整的治理闭环。

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能     | 接口                           | 是否需登录 |
| ---- | -------- | ------------------------------ | ---------- |
| F1   | 提交举报 | POST /user/reports             | 是         |
| F2   | 我的举报 | GET /user/reports              | 是         |
| F3   | 举报详情 | GET /user/reports/{id}         | 是         |
| F4   | 提交申诉 | POST /user/reports/{id}/appeal | 是         |

### 2.2 提交举报

**流程：**

1. 从 BaseContext 取 userId
2. 校验举报对象存在，获取被举报人 ID
3. 校验不能举报自己
4. 校验不能重复举报（同一人 + 同一对象）
5. 处理图片文件（校验归属、标记 used）
6. 构造 Report，status = pending
7. 插入 report 记录
8. 返回举报 ID

**入参：**

| 参数         | 类型       | 必填 | 约束               |
| ------------ | ---------- | ---- | ------------------ |
| targetType   | String     | 是   | product/user/order |
| targetId     | Long       | 是   | 举报对象ID         |
| reason       | String     | 是   | 最长 100 字符      |
| description  | String     | 否   | 最长 500 字符      |
| imageFileIds | List<Long> | 否   | 最多 9 张          |

**返回：** Result<Long>（举报 ID）

### 2.3 举报对象校验

不同 targetType 有不同的校验和"被举报人"判定逻辑：

| targetType | 校验     | 被举报人                     |
| ---------- | -------- | ---------------------------- |
| product    | 商品存在 | 商品的 sellerId              |
| user       | 用户存在 | 被举报用户本人               |
| order      | 订单存在 | 买家举报→卖家，卖家举报→买家 |

### 2.4 我的举报

**流程：**

1. 从 BaseContext 取 userId
2. 按 reporterId 查举报
3. 按创建时间倒序
4. 分页返回

**入参：**

| 参数     | 类型    | 必填 | 说明    |
| -------- | ------- | ---- | ------- |
| pageNum  | Integer | 否   | 默认 1  |
| pageSize | Integer | 否   | 默认 10 |

**返回：** Result<PageResult>

### 2.5 举报详情

**流程：**

1. 从 BaseContext 取 userId
2. 查举报，不存在报错
3. 校验 userId == reporterId（只有举报人能看）
4. 返回完整信息

**返回：** Result<ReportVO>

### 2.6 提交申诉

**流程：**

1. 从 BaseContext 取 userId
2. 查举报，不存在报错
3. 校验举报已处理（status != pending）
4. 校验 userId 是被举报人
5. 校验未申诉过
6. 处理图片文件
7. 构造 Appeal，status = pending
8. 插入 appeal 记录
9. 返回申诉 ID

**入参：**

| 参数         | 类型       | 必填 | 约束          |
| ------------ | ---------- | ---- | ------------- |
| reason       | String     | 是   | 最长 500 字符 |
| imageFileIds | List<Long> | 否   | 最多 9 张     |

**返回：** Result<Long>（申诉 ID）

## 三、数据库设计

### 3.1 report 表

```sql
CREATE TABLE IF NOT EXISTS `report` (
    `id`            BIGINT       NOT NULL COMMENT '主键',
    `reporter_id`   BIGINT       NOT NULL COMMENT '举报人ID',
    `target_type`   VARCHAR(20)  NOT NULL COMMENT '举报对象类型 product/user/order',
    `target_id`     BIGINT       NOT NULL COMMENT '举报对象ID',
    `reason`        VARCHAR(100) NOT NULL COMMENT '举报原因（短）',
    `description`   VARCHAR(500) DEFAULT NULL COMMENT '详细描述',
    `images`        VARCHAR(2000) DEFAULT NULL COMMENT '证据图片URL列表，逗号分隔',
    `status`        VARCHAR(20)  NOT NULL DEFAULT 'pending' COMMENT '状态 pending/valid/invalid',
    `action`        VARCHAR(20)  DEFAULT NULL COMMENT '处理动作 none/offline/ban/warn',
    `handle_reason` VARCHAR(255) DEFAULT NULL COMMENT '处理说明',
    `handler_id`    BIGINT       DEFAULT NULL COMMENT '处理管理员ID',
    `handle_time`   DATETIME     DEFAULT NULL COMMENT '处理时间',
    `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`       TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_reporter_id` (`reporter_id`),
    KEY `idx_target` (`target_type`, `target_id`),
    KEY `idx_status` (`status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '举报表';
```

### 3.2 字段说明

| 字段          | 说明               | 约束                  |
| ------------- | ------------------ | --------------------- |
| id            | 主键，雪花算法生成 | 唯一                  |
| reporter_id   | 举报人ID           | 关联 user.id          |
| target_type   | 举报对象类型       | product/user/order    |
| target_id     | 举报对象ID         | 关联对应表            |
| reason        | 举报原因（短）     | 非空，最长 100        |
| description   | 详细描述           | 最长 500              |
| images        | 证据图片           | 逗号分隔的URL         |
| status        | 处理状态           | pending/valid/invalid |
| action        | 处理动作           | none/offline/ban/warn |
| handle_reason | 处理说明           | 最长 255              |
| handler_id    | 处理管理员ID       | 关联 admin.id         |
| handle_time   | 处理时间           | -                     |

### 3.3 举报状态

| status  | 含义     | 触发           |
| ------- | -------- | -------------- |
| pending | 待处理   | 用户刚提交     |
| valid   | 举报成立 | 管理员判定有效 |
| invalid | 举报无效 | 管理员判定无效 |

### 3.4 处理动作

| action  | 含义                       |
| ------- | -------------------------- |
| none    | 不处罚（举报成立但只警告） |
| offline | 强制下架商品               |
| ban     | 封禁用户                   |
| warn    | 警告用户                   |

### 3.5 appeal 表

```sql
CREATE TABLE IF NOT EXISTS `appeal` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `report_id`   BIGINT       NOT NULL COMMENT '举报ID',
    `user_id`     BIGINT       NOT NULL COMMENT '申诉人ID（被举报人）',
    `reason`      VARCHAR(500) NOT NULL COMMENT '申诉理由',
    `images`      VARCHAR(2000) DEFAULT NULL COMMENT '证据图片URL列表',
    `status`      VARCHAR(20)  NOT NULL DEFAULT 'pending' COMMENT 'pending/approved/rejected',
    `handle_reason` VARCHAR(255) DEFAULT NULL COMMENT '处理说明',
    `handler_id`  BIGINT       DEFAULT NULL COMMENT '处理管理员ID',
    `handle_time` DATETIME     DEFAULT NULL COMMENT '处理时间',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_report` (`report_id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_status` (`status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '申诉表';
```

### 3.6 申诉状态

| status   | 含义                   |
| -------- | ---------------------- |
| pending  | 待处理                 |
| approved | 申诉通过（撤销处罚）   |
| rejected | 申诉被驳回（维持处罚） |

### 3.7 关键索引

**唯一索引 `uk_report`：**

```sql
UNIQUE KEY `uk_report` (`report_id`)
```

**作用：** 一个举报只能对应一条申诉，防止重复申诉。

### 3.8 表关系

```
user   1---N report (作为举报人)
user   1---N appeal (作为申诉人)
report 1---1 appeal
```

## 四、图片存储设计

### 4.1 存储方式

`report.images` 和 `appeal.images` 都是 `VARCHAR(2000)`，存**逗号分隔的 URL 字符串**：

```
https://oss.xxx.com/a.jpg,https://oss.xxx.com/b.jpg
```

### 4.2 Java 侧的处理

| 位置   | 类型                |
| ------ | ------------------- |
| 数据库 | VARCHAR（逗号分隔） |
| Entity | String              |
| VO     | List<String>        |

**复用评价模块的 TypeHandler：**

```java
com.example.handler.CommaSeparatedStringListTypeHandler
```

**Mapper XML 里指定：**

```xml
<result property="images" column="images"
        typeHandler="com.example.handler.CommaSeparatedStringListTypeHandler"/>
```

## 五、安全设计

### 5.1 举报权限校验

| 校验项       | 说明                       |
| ------------ | -------------------------- |
| 举报对象存在 | 不存在报错                 |
| 不能举报自己 | 商品/用户/订单不能举报自己 |
| 不能重复举报 | 同一人 + 同一对象只能一次  |
| 图片归属     | 通过 fileId 校验           |

### 5.2 申诉权限校验

| 校验项     | 说明                 |
| ---------- | -------------------- |
| 举报存在   | 不存在报错           |
| 举报已处理 | pending 不能申诉     |
| 是被举报人 | 只有被举报人能申诉   |
| 未申诉过   | 一条举报只能申诉一次 |

### 5.3 详情查看权限

**只有举报人能查看举报详情**，被举报人不能看到举报详情（只能看到处理结果）。

**原因：** 防止举报人信息泄露，避免被举报人报复。

### 5.4 图片归属校验

通过 `fileService.getFileOwnedByUser(fileId, userId)` 校验：

```
1. 查 file 表
2. 判断 file.userId == 当前 userId
   ├─ 匹配 → 继续
   └─ 不匹配 → 报错"无权使用该文件"
```

### 5.5 公开访问范围

| 接口     | 是否公开 |
| -------- | -------- |
| 提交举报 | ❌ 需登录 |
| 我的举报 | ❌ 需登录 |
| 举报详情 | ❌ 需登录 |
| 提交申诉 | ❌ 需登录 |

**举报模块所有接口都需登录。**

## 十、设计决策记录

| 决策               | 选择                  | 原因                     |
| ------------------ | --------------------- | ------------------------ |
| 举报对象           | 商品/用户/订单        | 覆盖主要违规场景         |
| 重复举报限制       | 同一人+同一对象       | 防刷                     |
| 举报人不能举报自己 | 校验                  | 防恶意                   |
| 举报状态           | pending/valid/invalid | 简单清晰                 |
| 处理动作           | none/offline/ban/warn | 覆盖主要处罚             |
| 申诉唯一性         | uk_report             | 一条举报一次申诉         |
| 申诉条件           | 举报已处理            | 未处理无申诉意义         |
| 举报详情权限       | 仅举报人              | 保护举报人隐私           |
| 图片存储           | 逗号分隔的 VARCHAR    | 复用评价模块 TypeHandler |
| 举报处理           | 管理端手动            | 避免误判                 |
| 事务               | 图片处理在同一事务    | 保证一致性               |
