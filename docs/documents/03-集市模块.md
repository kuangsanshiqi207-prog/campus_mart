# 市集模块设计文档

> 模块：市集（买家视角）
> 版本：V1.0
> 更新日期：2026-09-23

---

## 一、模块概述

市集模块是用户端的买家视角模块，负责让用户发现、浏览、搜索、收藏商品。所有登录用户可以同时作为买家使用本模块。

### 1.1 模块职责

| 职责          | 说明                                           |
| ------------- | ---------------------------------------------- |
| 商品列表/搜索 | 关键词、分类、价格区间、成色筛选，支持多种排序 |
| 商品详情      | 展示商品完整信息、图片、卖家信息，记录浏览量   |
| 首页推荐      | 展示热门商品                                   |
| 相似商品      | 同分类的其他商品                               |
| 卖家主页      | 查看卖家的基本信息、信用分、在售商品数         |
| 分类列表      | 展示启用的商品分类                             |
| 收藏商品      | 收藏/取消收藏，查看收藏列表                    |
| 浏览历史      | 记录用户浏览过的商品，支持清空                 |

### 1.2 模块边界

**做：**

- 商品浏览、搜索、筛选、排序
- 商品详情展示
- 收藏管理
- 浏览历史管理

**不做：**

- 商品发布、编辑、上下架（属于"我的商店"模块）
- 交易申请（属于交易模块）
- 商品审核（属于管理端）

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能          | 接口                                      | 是否需登录 |

| F3   | 商品详情      | GET /user/market/products/{id}            | 否         |
| F4   | 相似商品      | GET /user/market/products/{id}/similar    | 否         |
| F5   | 卖家主页      | GET /user/market/products/{id}/seller     | 否         |
| F6   | 分类列表      | GET /user/market/categories               | 否         |
| F7   | 收藏商品      | POST /user/market/favorites/{productId}   | 是         |

### 2.2 商品列表/搜索

**流程：**

1. 接收查询参数
2. 校验分页参数，默认 pageNum=1，pageSize=10
3. 组装查询条件：
   - keyword：模糊匹配 title
   - categoryId：按分类筛选
   - minPrice / maxPrice：价格区间
   - condition：成色
   - sort：排序方式
4. 只查审核通过（audit_status=approved）且在售（status=on_sale）的商品
5. 关联查分类名、卖家昵称、封面图
6. 分页返回

**入参：**

| 参数       | 类型       | 必填 | 说明                            |
| ---------- | ---------- | ---- | ------------------------------- |
| keyword    | String     | 否   | 搜索关键词                      |
| categoryId | Long       | 否   | 分类ID                          |
| minPrice   | BigDecimal | 否   | 最低价                          |
| maxPrice   | BigDecimal | 否   | 最高价                          |
| condition  | String     | 否   | 成色                            |
| sort       | String     | 否   | latest/price_asc/price_desc/hot |
| pageNum    | Integer    | 否   | 默认 1                          |
| pageSize   | Integer    | 否   | 默认 10                         |

**排序方式：**

| sort 值    | 含义                  |
| ---------- | --------------------- |
| latest     | 最新发布（默认）      |
| price_asc  | 价格升序              |
| price_desc | 价格降序              |
| hot        | 热度（浏览量+收藏数） |

**返回：** Result<PageResult>

### 2.3 首页推荐

**流程：**

1. 按浏览量降序、收藏数降序、发布时间降序
2. 只查审核通过且在售的商品
3. 分页返回

**说明：** MVP 阶段用"最热"策略，不做个性化推荐。后续可基于用户行为优化。

**返回：** Result<PageResult>

### 2.4 商品详情

**流程：**

1. 查商品，不存在或未审核通过返回错误
2. 查商品图片列表
3. 查分类名
4. 查卖家信息（昵称、头像、信用分、认证状态、在售商品数）
5. 浏览量 +1
6. 若已登录，查是否已收藏
7. 若已登录，记录浏览历史（已存在则更新时间）
8. 返回详情

**返回：** Result<ProductDetailVO>

| 字段          | 类型         | 说明               |
| ------------- | ------------ | ------------------ |
| id            | Long         | 商品ID             |
| title         | String       | 标题               |
| description   | String       | 描述               |
| price         | BigDecimal   | 售价               |
| originalPrice | BigDecimal   | 原价               |
| condition     | String       | 成色               |
| categoryId    | Long         | 分类ID             |
| categoryName  | String       | 分类名             |
| tradeType     | String       | 交易方式           |
| tradePlace    | String       | 交易地点           |
| status        | String       | 状态               |
| images        | List<String> | 图片URL列表        |
| seller        | SellerVO     | 卖家信息           |
| viewCount     | Integer      | 浏览量             |
| favoriteCount | Integer      | 收藏数             |
| favorited     | Boolean      | 当前用户是否已收藏 |
| createTime    | DateTime     | 发布时间           |

### 2.5 相似商品

**流程：**

1. 查当前商品，拿 categoryId
2. 查同分类其他商品（排除自己）
3. 按浏览量降序
4. 返回最多 10 条

**返回：** Result<List<ProductVO>>

### 2.6 卖家主页

**流程：**

1. 从商品 ID 反查 sellerId
2. 查卖家信息
3. 查卖家在售商品数
4. 返回

**返回：** Result<SellerVO>

| 字段         | 类型    | 说明         |
| ------------ | ------- | ------------ |
| id           | Long    | 卖家ID       |
| nickname     | String  | 昵称         |
| avatar       | String  | 头像         |
| creditScore  | Integer | 信用分       |
| certified    | Integer | 是否校园认证 |
| productCount | Integer | 在售商品数   |

### 2.7 分类列表

**流程：**

1. 查所有启用（status=1）的分类
2. 按 sort 升序
3. 返回

**返回：** Result<List<CategoryVO>>

### 2.8 收藏商品

**流程：**

1. 从 BaseContext 取 userId
2. 校验商品存在且审核通过
3. 检查是否已收藏（有则报错）
4. 生成雪花 ID
5. 插入 favorite 记录
6. 商品收藏数 +1

### 2.9 取消收藏

**流程：**

1. 从 BaseContext 取 userId
2. 检查是否已收藏（无则报错）
3. 删除 favorite 记录
4. 商品收藏数 -1（用 GREATEST 防负数）

### 2.10 我的收藏

**流程：**

1. 从 BaseContext 取 userId
2. 按 userId 查 favorite 记录
3. 关联查商品信息（用 INNER JOIN，已删除商品自动过滤）
4. 分页返回

### 2.11 浏览历史

**记录时机：** 查看商品详情时异步记录

**去重逻辑：**

- 已有记录 → 更新 browse_time
- 无记录 → 插入新记录

**查询流程：**

1. 从 BaseContext 取 userId
2. 按 userId 查 browse_history
3. 关联查商品信息
4. 按 browse_time 倒序
5. 分页返回

### 2.12 清空浏览历史

**流程：**

1. 从 BaseContext 取 userId
2. 删除该用户所有历史记录

## 三、数据库设计

### 3.1 category 表

```sql
CREATE TABLE IF NOT EXISTS `category` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `name`        VARCHAR(50)  NOT NULL COMMENT '分类名',
    `parent_id`   BIGINT       NOT NULL DEFAULT 0 COMMENT '父分类ID，0表示一级分类',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态 1启用 0禁用',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_parent_id` (`parent_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品分类表';
```

### 3.2 product 表

```sql
CREATE TABLE IF NOT EXISTS `product` (
    `id`             BIGINT        NOT NULL COMMENT '主键',
    `seller_id`      BIGINT        NOT NULL COMMENT '卖家ID',
    `category_id`    BIGINT        NOT NULL COMMENT '分类ID',
    `title`          VARCHAR(100)  NOT NULL COMMENT '标题',
    `description`    TEXT          COMMENT '描述',
    `price`          DECIMAL(10,2) NOT NULL COMMENT '售价',
    `original_price` DECIMAL(10,2) DEFAULT NULL COMMENT '原价',
    `quality`        VARCHAR(20)   NOT NULL DEFAULT 'good' COMMENT '成色',
    `trade_type`     VARCHAR(20)   NOT NULL DEFAULT 'face' COMMENT '交易方式',
    `trade_place`    VARCHAR(100)  DEFAULT NULL COMMENT '交易地点',
    `status`         VARCHAR(20)   NOT NULL DEFAULT 'on_sale' COMMENT '上架状态',
    `audit_status`   VARCHAR(20)   NOT NULL DEFAULT 'pending' COMMENT '审核状态',
    `audit_reason`   VARCHAR(255)  DEFAULT NULL COMMENT '审核拒绝原因',
    `view_count`     INT           NOT NULL DEFAULT 0 COMMENT '浏览量',
    `favorite_count` INT           NOT NULL DEFAULT 0 COMMENT '收藏数',
    `create_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`        TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_seller_id` (`seller_id`),
    KEY `idx_category_id` (`category_id`),
    KEY `idx_status` (`status`),
    KEY `idx_audit_status` (`audit_status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品表';
```

**字段说明：**

| 字段         | 说明     | 取值                                |
| ------------ | -------- | ----------------------------------- |
| status       | 上架状态 | on_sale / reserved / sold / offline |
| audit_status | 审核状态 | pending / approved / rejected       |
| quality      | 成色     | new / almost_new / good / normal    |
| trade_type   | 交易方式 | face / express / self_pickup        |

**注意：** 字段名用 `quality` 而不是 `condition`，因为 `condition` 是 MySQL 保留字。

### 3.3 product_image 表

```sql
CREATE TABLE IF NOT EXISTS `product_image` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `product_id`  BIGINT       NOT NULL COMMENT '商品ID',
    `url`         VARCHAR(500) NOT NULL COMMENT '图片URL',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序，0为封面',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_product_id` (`product_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品图片表';
```

### 3.4 favorite 表

```sql
CREATE TABLE IF NOT EXISTS `favorite` (
    `id`          BIGINT   NOT NULL COMMENT '主键',
    `user_id`     BIGINT   NOT NULL COMMENT '用户ID',
    `product_id`  BIGINT   NOT NULL COMMENT '商品ID',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_product` (`user_id`, `product_id`),
    KEY `idx_user_id` (`user_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '收藏表';
```

**设计说明：** 用 `uk_user_product` 唯一索引兜底，防止重复收藏。

### 3.5 browse_history 表

```sql
CREATE TABLE IF NOT EXISTS `browse_history` (
    `id`          BIGINT   NOT NULL COMMENT '主键',
    `user_id`     BIGINT   NOT NULL COMMENT '用户ID',
    `product_id`  BIGINT   NOT NULL COMMENT '商品ID',
    `browse_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '浏览时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_product` (`user_id`, `product_id`),
    KEY `idx_user_time` (`user_id`, `browse_time`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '浏览历史表';
```

**设计说明：** 用 `uk_user_product` 唯一索引去重，重复访问只更新时间。

### 3.6 表关系

```
category 1---N product
product  1---N product_image
user     M---N product  → favorite（中间表）
user     M---N product  → browse_history（中间表）
```

## 四、Redis 设计

MVP 阶段市集模块**未使用 Redis**。

### 4.1 MVP 存储策略

| 数据     | 存储              |
| -------- | ----------------- |
| 浏览量   | 直接 UPDATE MySQL |
| 收藏数   | 直接 UPDATE MySQL |
| 浏览历史 | 直接写 MySQL      |
| 收藏记录 | 直接写 MySQL      |

### 4.2 后期优化规划

| 场景     | 后期方案                           |
| -------- | ---------------------------------- |
| 浏览量   | Redis 计数器，定时批量同步到 MySQL |
| 收藏数   | Redis 计数器，实时同步             |
| 浏览历史 | Redis List，定期刷入 MySQL         |
| 商品详情 | Redis 缓存，TTL 10 分钟            |

### 4.3 为什么 MVP 不用 Redis

- 校园平台访问量小，MySQL 足够
- 浏览量 UPDATE 性能可接受
- 减少缓存一致性问题
- 后期遇到性能瓶颈再优化

## 五、安全设计

### 5.1 未登录访问

商品列表、详情、推荐、相似、分类这些接口**对未登录用户开放**。

实现方式：

- 拦截器放行 `/user/market/products/**` 和 `/user/market/categories`
- 需要登录的逻辑（收藏判断、记录历史）判断 `BaseContext.getCurrentId() != null`

### 5.2 收藏越权

收藏接口从 `BaseContext` 拿 userId，不接受前端传入的 userId，避免 A 用户给 B 用户收藏。

### 5.3 浏览历史越权

同收藏，从 `BaseContext` 拿 userId。

### 5.4 商品可见性

商品列表和详情只展示 `audit_status = approved` 且 `status = on_sale` 的商品。

未审核通过、已下架的商品不会展示给买家。

### 5.5 SQL 注入

所有 SQL 用 `#{}` 预编译参数，禁止用 `${}` 拼接。

`keyword` 用 `CONCAT('%', #{keyword}, '%')`，不直接拼字符串。

## 六、异常处理

### 6.1 业务异常

| 场景                 | 异常信息     |
| -------------------- | ------------ |
| 商品不存在           | 商品不存在   |
| 商品未审核通过       | 商品不存在   |
| 重复收藏             | 已收藏该商品 |
| 取消未收藏的商品     | 未收藏该商品 |
| 未登录访问需登录接口 | 用户未登录   |

### 6.2 参数校验异常

分页参数在 Service 层做默认值和范围检查：

- pageNum < 1 → 设为 1
- pageSize < 1 或 > 100 → 设为 10

### 6.3 未登录

拦截器返回 401，前端跳转登录页。

## 十、设计决策记录

| 决策          | 选择                       | 原因                         |
| ------------- | -------------------------- | ---------------------------- |
| 商品图片存储  | 独立表 product_image       | 一对多，支持多图             |
| 收藏存储      | 独立表 favorite            | 多对多，加唯一索引防重       |
| 浏览历史存储  | 独立表 browse_history      | 一对多，加唯一索引去重       |
| 分类设计      | 预留 parent_id             | MVP 只做一级，后期可扩展二级 |
| ID 生成       | Hutool 雪花算法            | 全局唯一，趋势递增           |
| 字段命名      | quality 代替 condition     | condition 是 MySQL 保留字    |
| 浏览量        | MVP 直接 UPDATE            | 简单，后期改 Redis           |
| 收藏数        | MVP 直接 UPDATE + GREATEST | 防并发负数                   |
| 浏览历史去重  | 数据库唯一索引             | 简单可靠                     |
| 推荐算法      | MVP 用"最热"               | 不做个性化，后期优化         |
| 收藏/历史查询 | INNER JOIN product         | 商品删除后自动过滤           |
| 未登录访问    | 部分接口放行               | 商品浏览不需要登录           |
| 收藏越权      | 从 BaseContext 取 userId   | 不接受前端传入               |
