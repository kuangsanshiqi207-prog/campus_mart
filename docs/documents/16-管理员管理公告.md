## 一、模块概述

公告管理模块是管理端的运营模块，负责平台公告的发布、修改、删除。公告由管理员发布，用户端可以查看已发布的公告。

### 1.1 模块职责

| 职责     | 说明                           |
| -------- | ------------------------------ |
| 公告列表 | 查询全平台公告，支持状态筛选   |
| 发布公告 | 创建新的公告，可存为草稿       |
| 修改公告 | 修改已有公告的标题、内容、状态 |
| 删除公告 | 逻辑删除公告                   |

### 1.2 模块边界

**做：**

- 公告的增删改查
- 公告状态管理（草稿/已发布）

**不做：**

- 用户端公告查看（属于用户端消息模块）
- 公告推送（属于消息推送后期优化）
- 公告内容审核（MVP 阶段不做）

### 1.3 与用户端公告接口的关系

| 数据     | 用户端消息模块      | 管理端公告管理       |
| -------- | ------------------- | -------------------- |
| 数据范围 | 只看 published      | 看全部（含 draft）   |
| 操作     | 只读                | 增删改查             |
| 路径     | /user/announcements | /admin/announcements |
| 权限     | 公开                | 管理员               |

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能     | 接口                             | 是否需登录 |
| ---- | -------- | -------------------------------- | ---------- |
| F1   | 公告列表 | GET /admin/announcements         | 是         |
| F2   | 发布公告 | POST /admin/announcements        | 是         |
| F3   | 修改公告 | PUT /admin/announcements/{id}    | 是         |
| F4   | 删除公告 | DELETE /admin/announcements/{id} | 是         |

### 2.2 公告列表

**流程：**

1. 接收查询条件（status、分页）
2. 组装 SQL 条件（status 可选）
3. 分页查询 announcement 表（deleted = 0）
4. 转 AnnouncementVO
5. 返回 PageResult

**入参：**

| 参数     | 类型    | 必填 | 说明            |
| -------- | ------- | ---- | --------------- |
| status   | String  | 否   | draft/published |
| pageNum  | Integer | 否   | 默认 1          |
| pageSize | Integer | 否   | 默认 10         |

**返回：** Result<PageResult<AnnouncementVO>>

| 字段       | 类型     | 说明            |
| ---------- | -------- | --------------- |
| id         | Long     | 公告ID          |
| title      | String   | 标题            |
| content    | String   | 内容            |
| status     | String   | draft/published |
| createTime | DateTime | 创建时间        |

### 2.3 发布公告

**流程：**

1. 从 BaseContext 取 adminId
2. 校验 status 合法（draft/published，默认 published）
3. 生成雪花 ID
4. 构造 Announcement，写入 adminId
5. 插入 announcement
6. 返回公告 ID

**入参：**

| 参数    | 类型   | 必填 | 约束           |
| ------- | ------ | ---- | -------------- |
| title   | String | 是   | 最长 100 字符  |
| content | String | 是   | 非空           |
| status  | String | 否   | 默认 published |

**返回：** Result<Long>

### 2.4 修改公告

**流程：**

1. 校验公告存在
2. 校验 status 合法（如传入）
3. 更新 announcement（title、content、status 按需更新）
4. 返回

**返回：** Result<Void>

### 2.5 删除公告

**流程：**

1. 校验公告存在
2. 逻辑删除 announcement（deleted = 1）
3. 返回

**返回：** Result<Void>

## 三、数据库设计

**复用消息模块已建的 announcement 表，不新增表。**

### 3.1 announcement 表

```sql
CREATE TABLE IF NOT EXISTS `announcement` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `title`       VARCHAR(100) NOT NULL COMMENT '标题',
    `content`     TEXT         NOT NULL COMMENT '内容',
    `status`      VARCHAR(20)  NOT NULL DEFAULT 'published' COMMENT 'draft/published',
    `admin_id`    BIGINT       DEFAULT NULL COMMENT '发布管理员ID',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_status` (`status`),
    KEY `idx_create_time` (`create_time`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '公告表';
```

### 3.2 状态说明

| status    | 说明               |
| --------- | ------------------ |
| draft     | 草稿，用户端不可见 |
| published | 已发布，用户端可见 |

### 3.3 表关系

```
admin 1---N announcement（发布者）
```

## 五、安全设计

### 5.1 权限隔离

管理端接口在 `/admin/announcements/**` 下：

- 用户 token 不能访问（type 校验）
- 只有管理员 token 能访问

### 5.2 操作权限

MVP 阶段，所有管理员都能操作公告管理功能。

**后续优化：** 按角色细分，公告发布可限制为运营角色。

### 5.3 关键操作留痕

| 操作     | 留痕                        |
| -------- | --------------------------- |
| 发布公告 | 记录 admin_id，可追溯发布者 |
| 修改公告 | update_time 自动更新        |
| 删除公告 | 逻辑删除，保留数据可审计    |

**后续优化：** 加管理员操作日志表，记录每次公告变更。

### 5.4 防止误操作

| 保护     | 说明                   |
| -------- | ---------------------- |
| 状态校验 | 只允许 draft/published |
| 逻辑删除 | 保留数据可追溯         |

## 十、设计决策记录

| 决策                 | 选择                         | 原因                           |
| -------------------- | ---------------------------- | ------------------------------ |
| 复用 announcement 表 | 不新增表                     | 数据结构一致                   |
| 公告状态             | draft/published              | 支持草稿，用户端只看 published |
| 发布记录 adminId     | 记录发布者                   | 便于追溯                       |
| 公告删除             | 逻辑删除                     | 保留数据用于审计               |
| 用户端接口           | 复用已有 /user/announcements | 无需修改                       |
| 权限                 | MVP 不细分角色               | 后期按角色控制                 |
| Mapper 复用          | 用户端 Mapper 追加方法       | 减少重复代码                   |
