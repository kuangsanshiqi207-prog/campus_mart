## 一、模块概述

管理端统计模块负责向管理员展示全平台的运营数据，包括用户、商品、订单、举报、AI审核等维度的概览和趋势。是平台运营监控的核心数据源。

### 1.1 模块职责

| 职责       | 说明                                             |
| ---------- | ------------------------------------------------ |
| 首页概览   | 用户/商品/订单总数及今日新增、待处理举报、待审核 |
| 用户统计   | 按天的用户新增趋势                               |
| 商品统计   | 按天的商品发布趋势                               |
| 订单统计   | 按天的订单创建趋势                               |
| 举报统计   | 举报总数、各状态分布、处理率                     |
| 审核统计   | 商品审核通过/拒绝分布                            |
| Excel 导出 | 导出各类统计数据为 Excel                         |

### 1.2 模块边界

**做：**

- 只读统计，不修改任何业务数据
- 数据来源：user、product、order、report
- 跨表聚合查询

**不做：**

- 数据的写入（属于各业务模块）
- 个人统计（属于用户端个人统计模块）
- AI 审核记录的明细统计（表未建，后期补充）
- 数据大屏（后期优化）

### 1.3 与管理端其他模块的区别

| 模块     | 用途               |
| -------- | ------------------ |
| 统计模块 | 只读，看趋势和概览 |
| 用户管理 | 增删改查用户数据   |
| 商品管理 | 增删改查商品数据   |
| 订单管理 | 处理订单           |
| 举报管理 | 处理举报和申诉     |
| 公告管理 | 发布公告           |

### 1.4 与用户端个人统计模块的区别

| 对比         | 个人统计           | 管理端统计      |
| ------------ | ------------------ | --------------- |
| 数据范围     | 只看自己           | 看全平台        |
| 目的         | 了解自己的交易情况 | 运营监控        |
| 权限         | 登录用户           | 管理员          |
| 路径         | /user/stats/**     | /admin/stats/** |
| 是否含信用分 | 是                 | 否              |
| 是否含导出   | 否                 | 是              |

### 2.2 首页概览

**流程：**

1. 查询 8 个指标：
   - user 表：总数、今日新增
   - product 表：总数、今日新增
   - order 表：总数、今日新增
   - report 表：待处理数
   - product 表：待审核数（audit_status = pending）
2. 组装 AdminOverviewVO
3. 返回

**返回：** Result<AdminOverviewVO>

| 字段          | 类型 | 说明         |
| ------------- | ---- | ------------ |
| userTotal     | Long | 用户总数     |
| userToday     | Long | 今日新增用户 |
| productTotal  | Long | 商品总数     |
| productToday  | Long | 今日新增商品 |
| orderTotal    | Long | 订单总数     |
| orderToday    | Long | 今日新增订单 |
| reportPending | Long | 待处理举报   |
| auditPending  | Long | 待审核商品   |

### 2.3 用户统计趋势

**流程：**

1. 接收日期范围（默认最近 30 天）
2. 按天查询 user 表的新增数量
3. 补齐没有数据的日期（值为 0）
4. 返回日期列表和数值列表

**入参：**

| 参数      | 类型      | 必填 | 说明                   |
| --------- | --------- | ---- | ---------------------- |
| startDate | LocalDate | 否   | 开始日期，默认 30 天前 |
| endDate   | LocalDate | 否   | 结束日期，默认今天     |

**返回：** Result<TrendVO>

| 字段   | 类型            | 说明                              |
| ------ | --------------- | --------------------------------- |
| dates  | List<LocalDate> | 日期列表，ISO 格式序列化          |
| values | List<Long>      | 对应日期的数值，长度与 dates 相等 |

### 2.4 商品统计趋势

同用户统计，数据来自 product 表。

### 2.5 订单统计趋势

同用户统计，数据来自 order 表。

### 2.6 AI审核统计

**流程：**

1. 从 product 表统计：
   - total：audit_status IN ('approved', 'rejected')
   - passCount：audit_status = 'approved'
   - rejectCount：audit_status = 'rejected'
2. manualCount = 0（MVP 阶段无人工复核）
3. avgConfidence = 0.0（MVP 阶段无置信度）
4. 返回

**返回：** Result<AuditStatsVO>

**说明：** MVP 阶段没有独立的 audit_record 表，从 product 表聚合统计。后期 AI 审核模块开发后，改为从 audit_record 表统计。

### 2.7 举报统计

**流程：**

1. 从 report 表一次聚合查询：
   - total、pending、valid、invalid
   - handleRate = (valid + invalid) / total * 100
2. 四舍五入到 2 位小数
3. 返回

**返回：** Result<ReportStatsVO>

| 字段       | 类型   | 说明        |
| ---------- | ------ | ----------- |
| total      | Long   | 举报总数    |
| pending    | Long   | 待处理      |
| valid      | Long   | 举报成立    |
| invalid    | Long   | 举报无效    |
| handleRate | Double | 处理率（%） |

### 2.8 Excel 导出

**流程：**

1. 接收 type 参数（users/products/orders/audits/reports）
2. 根据 type 生成对应数据：
   - users/products/orders → 最近 30 天趋势
   - reports → 举报统计概览
   - audits → 审核统计概览
3. 用 **POI 的 XSSFWorkbook** 写入 HttpServletResponse
4. 前端直接下载

**入参：**

| 参数 | 类型   | 必填 | 说明                                 |
| ---- | ------ | ---- | ------------------------------------ |
| type | String | 是   | users/products/orders/audits/reports |

**返回：** 二进制 Excel 文件

**为什么用 POI 而不是 EasyExcel：**

MVP 阶段数据量小（30 行以内），使用 EasyExcel 的 SXSSF 流式模式在 MockMvc 测试环境下会踩坑：

1. EasyExcel 默认用 SXSSFWorkbook（流式写 + 临时文件）
2. MockMvc 会在请求处理结束时立即关闭响应流
3. EasyExcel 的 dispose 阶段试图写流 → `Stream closed`
4. 异常链触发 EasyExcel 内部 Holder 的递归 hashCode → `StackOverflowError`
5. StackOverflowError 是 JVM 级别错误，会导致整个测试类崩溃

**改用 POI 的 XSSFWorkbook（全内存）：**

- 一次性构建完 Excel 内容
- 最后一刻写入响应流，立即 flush
- 不依赖响应流的长期可用性
- 测试环境和生产环境都稳定

### 2.9 趋势数据补齐

**问题：** SQL 只能查到有数据的日期。

**示例：** 用户 7 天没注册，8 天前和 9 天前各有 1 个，30 天查询时只能查到 2 个日期。

**解决方案：** Service 层补齐。

```
1. 生成完整的日期列表（startDate 到 endDate）
2. 把 SQL 结果放进 Map<日期字符串, 数值>
3. 遍历日期列表，从 Map 取值，没有则填 0
4. 返回等长的 dates 和 values
```

**好处：** 前端直接画图，不用处理缺失日期。

**实现要点：**

- `TrendVO.dates` 类型是 `List<LocalDate>`
- Map 的 key 用 `date.format("yyyy-MM-dd")` 字符串（和 SQL 返回值对齐）
- 逐个日期遍历，`dataMap.getOrDefault(key, 0L)` 兜底

## 三、数据库设计

**本模块不新增表**，只从已有表聚合查询。

### 3.1 数据来源

| 统计项       | 来源表  |
| ------------ | ------- |
| 用户总数     | user    |
| 今日新增用户 | user    |
| 商品总数     | product |
| 今日新增商品 | product |
| 订单总数     | order   |
| 今日新增订单 | order   |
| 待处理举报   | report  |
| 待审核商品   | product |
| 举报状态分布 | report  |
| 审核结果分布 | product |

### 3.2 SQL 设计要点

**1. 一次查询聚合多个指标**

```sql
SELECT
    COUNT(*) AS total,
    COALESCE(SUM(CASE WHEN status = 'pending' THEN 1 ELSE 0 END), 0) AS pending,
    COALESCE(SUM(CASE WHEN status = 'valid' THEN 1 ELSE 0 END), 0) AS valid,
    COALESCE(SUM(CASE WHEN status = 'invalid' THEN 1 ELSE 0 END), 0) AS invalid
FROM report
WHERE deleted = 0
```

**2. COALESCE 兜底**

没有数据时返回 0 而不是 NULL。

**3. 除零保护 + 浮点运算**

```sql
COALESCE(
    (SUM(CASE WHEN status IN ('valid', 'invalid') THEN 1 ELSE 0 END) * 100.0
     / NULLIF(COUNT(*), 0)),
    0
) AS handleRate
```

**关键点：**

- `NULLIF(COUNT(*), 0)` 防止除零
- **`* 100.0` 而不是 `* 100`**：MySQL 整数除法会截断，`5/10*100 = 0`，加小数才能得到 50.0
- `COALESCE` 兜底为 0

**4. 趋势按天分组**

```sql
SELECT DATE(create_time) AS date, COUNT(*) AS value
FROM user
WHERE deleted = 0
  AND create_time >= #{start}
  AND create_time < DATE_ADD(#{end}, INTERVAL 1 DAY)
GROUP BY DATE(create_time)
ORDER BY DATE(create_time) ASC
```

**注意：** 用 `< DATE_ADD(end, INTERVAL 1 DAY)` 而不是 `<= end`，避免时间部分影响（end 是 `yyyy-MM-dd 00:00:00`，用 `<=` 会漏掉 end 当天的数据）。

## 十一、踩坑记录（重点）

### 11.1 EasyExcel + MockMvc 的 Stream closed 问题

**现象：**

```
java.io.IOException: Stream closed
    at o.a.poi.xssf.streaming.SXSSFWorkbook.dispose
    at com.alibaba.excel.context.WriteContextImpl.finish
```

紧接着抛 `StackOverflowError`：

```
at WriteWorkbookHolder.hashCode
at WriteSheetHolder.hashCode
at WriteWorkbookHolder.hashCode  ← 循环
```

**根因：**

1. EasyExcel 默认用 `SXSSFWorkbook`（流式模式），依赖 response 流的长期可用性
2. MockMvc 在请求处理结束时立即关闭响应流
3. EasyExcel 在 dispose 阶段往已关闭的流里写 → `Stream closed`
4. 异常链触发 Holder 之间的循环引用递归 hashCode → `StackOverflowError`
5. StackOverflowError 是 JVM 级错误，JUnit 无法捕获，**整个测试类后续方法全部作废**

**为什么 `inMemory(Boolean.TRUE)` 没救回来：**

- EasyExcel 4.0.3 的 `inMemory` 参数在某些版本下不会真正切换为 XSSF
- 即使切换成功，某些 dispose 流程仍然会碰响应流

**解决方案：**

用 POI 的 `XSSFWorkbook` 直写：

```java
try (XSSFWorkbook workbook = new XSSFWorkbook()) {
    // 内存里构建全部内容
    Sheet sheet = workbook.createSheet(type);
    // ... 写表头和数据 ...
    // 一次性写到响应流
    workbook.write(response.getOutputStream());
    response.getOutputStream().flush();
}
```

**关键区别：**

| 项            | EasyExcel + SXSSF        | POI + XSSF         |
| ------------- | ------------------------ | ------------------ |
| 写入时机      | 分多次写，最后合并       | 一次性写           |
| 临时文件      | 有                       | 无                 |
| 对流的假设    | 流必须在整个写入期间可用 | 只在最后一刻需要流 |
| 生命周期      | 长                       | 短                 |
| Mock 环境兼容 | ❌ 流被提前关             | ✅ 稳过             |

**生产环境说明：** 真实 Servlet 环境下 EasyExcel 大概率不崩（Tomcat 响应流在请求结束才关），但为了测试能过 + 代码更健壮，用 POI 直写是更稳的选择。

### 11.2 整数除法截断

**现象：** `handleRate` 计算结果永远是 0。

**原因：**

```sql
(SUM(...) / COUNT(*)) * 100
```

MySQL 里 `5/10 = 0`（整数除法截断），`0 * 100 = 0`。

**解决：** 乘 100.0 而不是 100，走浮点运算：

```sql
(SUM(...) * 100.0 / NULLIF(COUNT(*), 0))
```

### 11.3 TrendVO.dates 类型不一致

**现象：** 编译报错 `incompatible types: List<LocalDate> cannot be converted to List<String>`。

**原因：** 用户端 `TrendVO.dates` 是 `List<LocalDate>`，管理端一开始按 `List<String>` 写。

**解决：** 管理端也用 `List<LocalDate>`，与用户端保持一致：

```java
List<LocalDate> dates = new ArrayList<>();
// ...
dates.add(cursor);              // 直接放 LocalDate 对象
String key = cursor.format(DATE_FMT);  // key 用字符串
values.add(dataMap.getOrDefault(key, 0L));
```
