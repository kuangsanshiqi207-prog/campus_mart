# 私信模块设计文档

> 模块：私信
> 版本：V1.0
> 更新日期：2026-09-24

---

## 一、模块概述

私信模块负责用户之间的即时通讯，是买卖双方沟通商品、议价、约定面交的核心工具。与消息模块（系统单向通知）不同，私信是双向多轮对话，需要实时推送。

### 1.1 模块职责

| 职责       | 说明                    |
| ---------- | ----------------------- |
| 创建会话   | 用户对商品/用户发起会话 |
| 会话列表   | 展示用户所有会话        |
| 历史消息   | 游标分页查询聊天记录    |
| 发送消息   | 用户之间互发消息        |
| 实时推送   | WebSocket 秒级送达      |
| 未读数管理 | 每个会话独立计数        |
| 已读回执   | 对方已读通知            |
| 心跳保活   | 检测连接状态            |

### 1.2 模块边界

**做：**

- 会话与消息的创建、查询
- WebSocket 实时推送
- 未读数、已读回执

**不做：**

- 系统通知（属于消息模块）
- 消息内容审核（属于 AI 审核模块）
- 群聊（只做一对一）

### 1.3 与消息模块的区别

| 对比     | 消息模块 | 私信模块        |
| -------- | -------- | --------------- |
| 发送方   | 系统     | 用户            |
| 方向     | 单向     | 双向            |
| 实时性   | 不需要   | WebSocket       |
| 数据模型 | 单表     | 会话表 + 消息表 |
| 能否回复 | 不能     | 能              |
| 类比例子 | 短信通知 | 微信聊天        |

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能           | 接口                                        | 是否需登录     |
| ---- | -------------- | ------------------------------------------- | -------------- |
| F1   | 创建/获取会话  | POST /user/chat/conversations               | 是             |
| F2   | 会话列表       | GET /user/chat/conversations                | 是             |
| F3   | 历史消息       | GET /user/chat/conversations/{id}/messages  | 是             |
| F4   | 发送消息       | POST /user/chat/conversations/{id}/messages | 是             |
| F5   | 标记已读       | PUT /user/chat/conversations/{id}/read      | 是             |
| F6   | 删除会话       | DELETE /user/chat/conversations/{id}        | 是             |
| F7   | WebSocket 连接 | WS /ws/chat                                 | 是（握手校验） |

### 2.2 创建/获取会话

**流程：**

1. 从 BaseContext 取 userId
2. 校验不能和自己聊天
3. 校验对方用户存在
4. 取小 ID 在前：`userAId = min(me, target)`, `userBId = max(me, target)`
5. 查会话是否已存在（`getByUserPair`）
6. 存在则直接返回，不存在则新建
7. 返回会话 VO

**入参：**

| 参数         | 类型 | 必填 | 说明             |
| ------------ | ---- | ---- | ---------------- |
| targetUserId | Long | 是   | 对方用户 ID      |
| productId    | Long | 否   | 关联商品（可选） |

**返回：** Result<ConversationVO>

### 2.3 会话列表

**流程：**

1. 从 BaseContext 取 userId
2. 查询 `user_a_id = me OR user_b_id = me` 的所有会话
3. 按最后消息时间倒序
4. 关联查对方用户信息
5. 计算未读数（我是 A 取 a_unread，我是 B 取 b_unread）
6. 返回

**返回：** Result<List<ConversationVO>>

### 2.4 历史消息

**流程：**

1. 从 BaseContext 取 userId
2. 校验会话存在且自己是参与方
3. 游标分页：`WHERE conversation_id = ? AND id < lastId ORDER BY id DESC LIMIT limit`
4. 结果倒序转正序（老消息在上）
5. 返回

**入参：**

| 参数   | 类型    | 必填 | 说明                |
| ------ | ------- | ---- | ------------------- |
| lastId | Long    | 否   | 游标，上一页最小 ID |
| limit  | Integer | 否   | 默认 20，最大 100   |

**返回：** Result<List<ChatMessageVO>>

### 2.5 发送消息

**流程：**

1. 从 BaseContext 取 userId
2. 校验会话存在且自己是参与方
3. 确定接收者（对方 userId）
4. 插入 chat_message
5. 更新 conversation 的 last_message 和 last_message_at
6. 对方未读数 +1
7. 通过 WebSocket 推送 `chat` 事件给接收者
8. 返回消息 VO

**入参：**

| 参数    | 类型   | 必填 | 说明                     |
| ------- | ------ | ---- | ------------------------ |
| content | String | 是   | 最长 2000 字符           |
| type    | String | 否   | text/image/product/order |

**返回：** Result<ChatMessageVO>

### 2.6 标记已读

**流程：**

1. 从 BaseContext 取 userId
2. 校验会话存在且自己是参与方
3. `UPDATE chat_message SET status='read' WHERE conversation_id=? AND to_user_id=? AND status!='read'`
4. 清空自己的未读数
5. 通过 WebSocket 推送 `read` 事件给对方（已读回执）
6. 返回

**返回：** Result<Void>

### 2.7 删除会话

**流程：**

1. 从 BaseContext 取 userId
2. 校验会话存在且自己是参与方
3. 逻辑删除（`deleted = 1`）
4. 返回

## 三、数据库设计

### 3.1 conversation 表

```sql
CREATE TABLE IF NOT EXISTS `conversation` (
    `id`              BIGINT   NOT NULL COMMENT '主键',
    `user_a_id`       BIGINT   NOT NULL COMMENT '用户A（小ID）',
    `user_b_id`       BIGINT   NOT NULL COMMENT '用户B（大ID）',
    `last_message`    VARCHAR(500) DEFAULT NULL COMMENT '最后一条消息预览',
    `last_message_at` DATETIME DEFAULT NULL COMMENT '最后消息时间',
    `a_unread`        INT      NOT NULL DEFAULT 0 COMMENT 'A的未读数',
    `b_unread`        INT      NOT NULL DEFAULT 0 COMMENT 'B的未读数',
    `create_time`     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`         TINYINT  NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_pair` (`user_a_id`, `user_b_id`),
    KEY `idx_user_a` (`user_a_id`),
    KEY `idx_user_b` (`user_b_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '会话表';
```

### 3.2 关键设计

**小 ID 在前：**

```java
Long userAId = Math.min(userId, targetUserId);
Long userBId = Math.max(userId, targetUserId);
```

加上唯一索引 `uk_user_pair`，保证 (5, 8) 和 (8, 5) 只会有**一条会话记录**。

**未读数冗余：**

`a_unread`、`b_unread` 直接存到会话表里。

- 会话列表查询时直接读字段，不用 COUNT
- 用 `UPDATE conversation SET a_unread = a_unread + 1` 保证原子性

**last_message 冗余：**

会话列表要显示最后一条消息，直接存一份，不用查 message 表。

### 3.3 chat_message 表

```sql
CREATE TABLE IF NOT EXISTS `chat_message` (
    `id`              BIGINT       NOT NULL COMMENT '主键',
    `conversation_id` BIGINT       NOT NULL COMMENT '会话ID',
    `from_user_id`    BIGINT       NOT NULL COMMENT '发送者',
    `to_user_id`      BIGINT       NOT NULL COMMENT '接收者',
    `type`            VARCHAR(20)  NOT NULL DEFAULT 'text' COMMENT 'text/image/product/order',
    `content`         VARCHAR(2000) NOT NULL COMMENT '消息内容',
    `status`          VARCHAR(20)  NOT NULL DEFAULT 'sent' COMMENT 'sent/read',
    `create_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_conversation_id` (`conversation_id`, `id`),
    KEY `idx_to_user_read` (`to_user_id`, `status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '聊天消息表';
```

### 3.4 索引说明

| 索引                                        | 用途         |
| ------------------------------------------- | ------------ |
| `idx_conversation_id (conversation_id, id)` | 游标分页查询 |
| `idx_to_user_read (to_user_id, status)`     | 标记已读     |

### 3.5 表关系

```
user         1---N conversation（作为 A 或 B）
conversation 1---N chat_message
```

## 四、WebSocket 设计

### 4.1 连接地址

```
ws://localhost:8080/ws/chat?token={JWT}
```

**Token 放 URL 参数**，因为浏览器 WebSocket 握手时不支持自定义请求头。

### 4.2 握手拦截器

**位置：** `WebSocketAuthInterceptor`

**流程：**

1. 从 URL 解析 token
2. 去掉 Bearer 前缀
3. 解析 JWT 拿 userId
4. 把 userId 放入 session attributes
5. 放行 / 拒绝

### 4.3 连接管理

```java
Map<Long, WebSocketSession> SESSIONS;
```

- 用户上线：`SESSIONS.put(userId, session)`
- 用户下线：`SESSIONS.remove(userId)`
- 推送：`SESSIONS.get(toUserId).sendMessage(json)`

**单机版。**

### 4.4 消息协议

**服务端 → 客户端：**

| type | 说明     | 数据结构                               |
| ---- | -------- | -------------------------------------- |
| chat | 新消息   | `{type: "chat", data: ChatMessageVO}`  |
| read | 对方已读 | `{type: "read", conversationId: Long}` |
| pong | 心跳响应 | `{type: "pong"}`                       |

**客户端 → 服务端：**

| type | 说明            |
| ---- | --------------- |
| ping | 心跳，30 秒一次 |

**注意：** WebSocket 只用于**接收服务端推送**，发消息走 **HTTP POST**。

### 4.5 心跳机制

- 前端每 30 秒发 `{type: "ping"}`
- 后端回 `{type: "pong"}`
- 连续多次收不到 pong → 前端重连

### 4.6 断线重连

前端 `ws.onclose` 里 3 秒后自动重连。

### 4.7 为什么 WebSocket 不处理业务消息

**原来设计：** WebSocket 收发双向，`ChatWebSocketServer` 注入 `ChatService`。

**问题：** 形成循环依赖

```
ChatServiceImpl → ChatPushService → ChatWebSocketServer
                                          ↑
                                          └ 依赖 ChatService
```

Spring Boot 3.x 默认禁止循环依赖，启动直接报错。

**改后：** WebSocket 只推送，发消息走 HTTP。

```
ChatServiceImpl → ChatPushService → ChatWebSocketServer
                                        （不依赖 Service）
```

**好处：**

1. 无循环依赖
2. 发消息有 HTTP 响应，知道成功与否
3. 调试方便（HTTP 可见）

**这也是主流 IM 的做法。**

## 五、安全设计

### 5.1 会话权限校验

每个接口都校验当前用户是会话参与方：

```java
private boolean isParticipant(Conversation conversation, Long userId) {
    return conversation.getUserAId().equals(userId)
            || conversation.getUserBId().equals(userId);
}
```

不匹配抛"无权操作该会话"。

### 5.2 WebSocket 鉴权

握手时校验 token，校验失败直接拒绝连接。

### 5.3 不能和自己聊天

```java
if (userId.equals(targetUserId)) {
    throw new BaseException(MessageConstant.CHAT_CANNOT_SEND_TO_SELF);
}
```

### 5.4 消息内容限制

- 最长 2000 字符
- 通过 `@Size` 校验

### 5.5 公开访问范围

**私信模块所有接口都需要登录**，包括 WebSocket 握手。

## 十、设计决策记录

| 决策           | 选择                       | 原因                             |
| -------------- | -------------------------- | -------------------------------- |
| 会话唯一性     | 小 ID 在前 + 唯一索引      | 防止重复会话                     |
| 未读数         | 冗余在会话表               | 查询快，不用 COUNT               |
| 消息存储       | MySQL                      | 离线消息不丢                     |
| 实时推送       | WebSocket                  | 秒级到达                         |
| 游标分页       | id < lastId                | 避免 offset 重复问题             |
| Token 位置     | URL 参数                   | WebSocket 握手不支持自定义头     |
| 发消息通道     | HTTP POST                  | 无循环依赖，有响应               |
| WebSocket 职责 | 只推送                     | 避免循环依赖                     |
| ObjectMapper   | 自定义 JacksonObjectMapper | 支持 Long→String + LocalDateTime |

## 十一、踩坑记录（重点）

联调过程中踩过的坑，值得记下来。

### 11.1 循环依赖

**报错：**

```
The dependencies of some of the beans in the application context form a cycle:
   chatController → chatServiceImpl → chatPushServiceImpl → chatWebSocketServer
```

**原因：** `ChatWebSocketServer` 依赖 `ChatService`，`ChatService` 又依赖 `ChatPushService`。

**解决：** WebSocket 只推送，发消息走 HTTP。

### 11.2 雪花 ID 精度丢失

**现象：** 会话 ID 从 `...1712` 变成 `...1700`，导致所有接口返回"会话不存在"。

**原因：** JS 的 Number 最大安全整数是 `2^53 - 1`（16 位），雪花 ID 是 19 位，超出范围。

**解决：** `JacksonObjectMapper` 里配置 `Long → String`：

```java
SimpleModule simpleModule = new SimpleModule()
        .addSerializer(Long.class, ToStringSerializer.instance)
        .addSerializer(Long.TYPE, ToStringSerializer.instance);
this.registerModule(simpleModule);
```

### 11.3 LocalDateTime 序列化失败

**报错：**

```
InvalidDefinitionException: Java 8 date/time type `java.time.LocalDateTime` not supported by default
```

**原因：** `ChatWebSocketServer` 里 `new ObjectMapper()` 用的是 Jackson 默认配置，不认 Java 8 时间类型。

**解决：** 改用项目自定义的 `JacksonObjectMapper`。

```java
private final ObjectMapper objectMapper = new JacksonObjectMapper();
```

### 11.4 前端 onclick 字符串拼接丢精度

**现象：** 会话列表渲染时 ID 正确，点击时 ID 变成 `...1700`。

**原因：**

```javascript
onclick="openConversation(${c.id})"  // 字符串被当数字解析，丢精度
```

**解决：** ID 加引号

```javascript
onclick="openConversation('${c.id}')"
```

**正式用 Vue 后不会有这个问题**（用函数绑定，不走 HTML 字符串解析）。

### 11.5 Nginx 路径多一层

**报错：** `GetFileAttributesEx() "E:\download\nginx-1.24.0\nginx-1.24.0\html/index.html" failed`

**原因：** `root html` 是相对路径，基于启动目录解析，路径多了一层。

**解决：** 用绝对路径 `root E:/download/nginx-1.24.0/html;`。

### 11.6 CORS 跨域

**报错：** `No 'Access-Control-Allow-Origin' header is present on the requested resource`

**原因：** `WebMvcConfiguration extends WebMvcConfigurationSupport` 导致 CorsConfig 失效。

**解决：** 改成 `implements WebMvcConfigurer`，拦截器放行 OPTIONS。

**更好方案：** Nginx 反代，前后端同源，不需要 CORS。
