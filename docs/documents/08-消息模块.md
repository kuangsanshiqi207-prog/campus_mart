## 一、模块概述

消息模块负责系统向用户发送站内通知和平台公告，是用户了解交易进度、审核结果、平台动态的重要渠道。消息为单向通知，用户只需读取，无需回复。

### 1.1 模块职责

| 职责     | 说明                         |
| -------- | ---------------------------- |
| 站内信   | 系统向用户发送各类通知       |
| 公告管理 | 管理员发布平台公告，用户查看 |
| 未读统计 | 展示用户未读消息数           |
| 已读标记 | 支持单条已读和全部已读       |
| 消息删除 | 逻辑删除消息                 |
| 消息推送 | 供其他模块调用发送消息       |

### 1.2 模块边界

**做：**

- 系统通知的发送、查询、已读、删除
- 平台公告的展示
- 为其他模块提供消息发送能力

**不做：**

- 用户间聊天（属于私信模块）
- 消息推送通道（短信、微信订阅消息，后期扩展）
- 消息内容审核（属于管理端）

### 1.3 与私信模块的区别

| 对比     | 消息模块 | 私信模块        |
| -------- | -------- | --------------- |
| 发送方   | 系统     | 用户            |
| 接收方   | 用户     | 用户            |
| 方向     | 单向     | 双向            |
| 能否回复 | 不能     | 能              |
| 实时性   | 不需要   | 需要 WebSocket  |
| 数据模型 | 单表     | 会话表 + 消息表 |
| 类比例子 | 短信通知 | 微信聊天        |

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能       | 接口                            | 是否需登录 |
| ---- | ---------- | ------------------------------- | ---------- |
| F1   | 消息列表   | GET /user/messages              | 是         |
| F2   | 未读消息数 | GET /user/messages/unread-count | 是         |
| F3   | 标记已读   | PUT /user/messages/{id}/read    | 是         |
| F4   | 全部已读   | PUT /user/messages/read-all     | 是         |
| F5   | 删除消息   | DELETE /user/messages/{id}      | 是         |
| F6   | 公告列表   | GET /user/announcements         | 否         |
| F7   | 公告详情   | GET /user/announcements/{id}    | 否         |

### 2.2 消息列表

**流程：**

1. 从 BaseContext 取 userId
2. 按 userId 查消息
3. 可选按 type 筛选（order/audit/report/system）
4. 可选按 isRead 筛选（0未读 / 1已读）
5. 按创建时间倒序
6. 分页返回

**入参：**

| 参数     | 类型    | 必填 | 说明          |
| -------- | ------- | ---- | ------------- |
| type     | String  | 否   | 消息类型      |
| isRead   | Integer | 否   | 0未读 / 1已读 |
| pageNum  | Integer | 否   | 默认 1        |
| pageSize | Integer | 否   | 默认 10       |

**返回：** Result<PageResult>

### 2.3 未读消息数

**流程：**

1. 从 BaseContext 取 userId
2. 统计 is_read = 0 的消息数
3. 返回

**返回：** Result<Long>

### 2.4 标记已读

**流程：**

1. 从 BaseContext 取 userId
2. 查消息，不存在报错
3. 校验 userId 匹配（防越权）
4. 更新 is_read = 1
5. 返回成功

**返回：** Result<Void>

### 2.5 全部已读

**流程：**

1. 从 BaseContext 取 userId
2. 将该用户所有未读消息改为已读
3. 返回成功

**返回：** Result<Void>

### 2.6 删除消息

**流程：**

1. 从 BaseContext 取 userId
2. 查消息，不存在报错
3. 校验 userId 匹配（防越权）
4. 逻辑删除
5. 返回成功

**返回：** Result<Void>

### 2.7 公告列表

**流程：**

1. 查 status = published 的公告
2. 按发布时间倒序
3. 分页返回

**返回：** Result<PageResult>

### 2.8 公告详情

**流程：**

1. 按 id 查公告
2. 不存在报错
3. 返回完整信息

**返回：** Result<AnnouncementVO>

## 三、数据库设计

### 3.1 message 表

```sql
CREATE TABLE IF NOT EXISTS `message` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `user_id`     BIGINT       NOT NULL COMMENT '接收者ID',
    `type`        VARCHAR(20)  NOT NULL COMMENT '消息类型 order/audit/report/system',
    `title`       VARCHAR(100) NOT NULL COMMENT '标题',
    `content`     VARCHAR(500) NOT NULL COMMENT '内容',
    `biz_id`      BIGINT       DEFAULT NULL COMMENT '关联业务ID（订单ID/商品ID等）',
    `is_read`     TINYINT      NOT NULL DEFAULT 0 COMMENT '是否已读 0未读 1已读',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_user_read` (`user_id`, `is_read`),
    KEY `idx_create_time` (`create_time`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '消息表';
```

### 3.2 字段说明

| 字段    | 说明               | 约束                      |
| ------- | ------------------ | ------------------------- |
| id      | 主键，雪花算法生成 | 唯一                      |
| user_id | 接收者ID           | 关联 user.id              |
| type    | 消息类型           | order/audit/report/system |
| title   | 标题               | 最长 100                  |
| content | 内容               | 最长 500                  |
| biz_id  | 关联业务ID         | 订单ID/商品ID等           |
| is_read | 是否已读           | 0未读 1已读               |
| deleted | 逻辑删除           | 默认 0                    |

### 3.3 消息类型说明

| type   | 说明     | biz_id 含义   |
| ------ | -------- | ------------- |
| order  | 交易相关 | orderId       |
| audit  | 审核相关 | 认证ID/商品ID |
| report | 举报相关 | reportId      |
| system | 系统通知 | 无            |

### 3.4 announcement 表

```sql
CREATE TABLE IF NOT EXISTS `announcement` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `title`       VARCHAR(100) NOT NULL COMMENT '标题',
    `content`     TEXT         NOT NULL COMMENT '内容',
    `status`      VARCHAR(20)  NOT NULL DEFAULT 'published' COMMENT 'draft/published',
    `admin_id`    BIGINT       DEFAULT NULL COMMENT '发布管理员ID',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_status` (`status`),
    KEY `idx_create_time` (`create_time`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '公告表';
```

### 3.5 公告状态

| status    | 说明               |
| --------- | ------------------ |
| draft     | 草稿，用户端不可见 |
| published | 已发布，用户端可见 |

### 3.6 表关系

```
user 1---N message
announcement 独立表
```

### 4.3 联动关系

| 触发操作 | 操作人 | 接收人   | 消息标题       |
| -------- | ------ | -------- | -------------- |
| 申请交易 | 买家   | 卖家     | 新的交易申请   |
| 接受交易 | 卖家   | 买家     | 交易申请已接受 |
| 拒绝交易 | 卖家   | 买家     | 交易申请被拒绝 |
| 取消订单 | 任一方 | 对方     | 订单已取消     |
| 完成交易 | 买家   | 双方     | 交易已完成     |
| 发表评价 | 任一方 | 被评价人 | 收到新评价     |

### 4.4 事务一致性

消息发送在业务方法的事务内：

```java
@Transactional
public void acceptOrder(Long id) {
    orderMapper.updateStatus(...);
    productMapper.updateStatus(...);
    messageSender.send(...);   // 同一事务
}
```

**好处：** 消息写库失败时，订单状态也会回滚，保证一致性。
**代价：** 消息写库增加事务时长。
**后期优化：** 用消息队列异步发消息。

## 五、安全设计

### 5.1 越权防护

标记已读、删除消息必须校验消息归属：

```
1. 从 BaseContext 取 userId
2. 查消息
3. 判断 message.userId == userId
   ├─ 匹配 → 继续
   └─ 不匹配 → 报错"无权操作该消息"
```

### 5.2 公开接口

| 接口     | 是否公开 |
| -------- | -------- |
| 消息列表 | ❌ 需登录 |
| 未读数   | ❌ 需登录 |
| 标记已读 | ❌ 需登录 |
| 全部已读 | ❌ 需登录 |
| 删除消息 | ❌ 需登录 |
| 公告列表 | ✅ 公开   |
| 公告详情 | ✅ 公开   |

**公告公开，未登录用户也能看。**

### 5.3 拦截器放行

```java
.excludePathPatterns(
        // ... 其他放行路径
        "/user/announcements",
        "/user/announcements/*"     // 注意：一级子路径用 *
);
```

**注意：** Ant 路径匹配中，`/user/announcements` 只匹配自身，`/user/announcements/*` 匹配一级子路径。

## 十、设计决策记录

| 决策       | 选择               | 原因                         |
| ---------- | ------------------ | ---------------------------- |
| 消息模型   | 单表               | 单向通知，结构简单           |
| 消息发送   | MessageSender 接口 | 供其他模块解耦调用           |
| 事务一致性 | 同一事务           | 保证消息与业务同时成功或失败 |
| 消息删除   | 逻辑删除           | 保留历史数据                 |
| 公告公开   | 匿名可看           | 提高平台透明度               |
| 消息类型   | 字符串枚举         | 可读性好                     |
| biz_id     | 存关联业务ID       | 前端可跳转                   |
| 后期优化   | 消息队列异步       | 减少事务时长                 |
