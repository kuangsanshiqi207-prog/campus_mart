> 版本：V1.0
> 更新日期：2026-09-24

## 一、模块概述

我的商店模块是用户端的卖家视角模块，负责商品的发布、编辑、上下架和数据查看。所有用户都可以作为卖家使用本模块。

### 1.1 模块职责

| 职责         | 说明                             |
| ------------ | -------------------------------- |
| 发布商品     | 填写商品信息，上传图片，创建商品 |
| 修改商品     | 编辑自己的商品信息               |
| 删除商品     | 逻辑删除自己的商品               |
| 下架商品     | 将商品从在售改为已下架           |
| 重新上架     | 将已下架商品恢复在售             |
| 我的商品列表 | 查看自己所有状态的商品           |
| 我的商品详情 | 查看自己商品的完整信息           |
| 我的商品统计 | 查看各状态数量和浏览收藏总数     |

### 1.2 模块边界

**做：**

- 商品全生命周期管理（发布、编辑、删除、上下架）
- 卖家自己的商品数据查看

**不做：**

- 浏览、搜索、收藏其他商品（属于市集模块）
- 交易申请（属于交易模块）
- 商品审核（属于管理端商品管理）

### 1.3 与市集模块的区别

| 对比       | 市集模块              | 我的商店模块       |
| ---------- | --------------------- | ------------------ |
| 视角       | 买家                  | 卖家               |
| 核心操作   | 浏览、搜索、收藏      | 发布、编辑、上下架 |
| 数据范围   | 全平台商品            | 只看自己的商品     |
| 商品可见性 | 仅 on_sale + approved | 所有状态           |
| 路径       | /user/market/**       | /user/shop/**      |

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能         | 接口                                 | 是否需登录 |
| ---- | ------------ | ------------------------------------ | ---------- |
| F1   | 发布商品     | POST /user/shop/products             | 是         |
| F2   | 修改商品     | PUT /user/shop/products/{id}         | 是         |
| F3   | 删除商品     | DELETE /user/shop/products/{id}      | 是         |
| F4   | 下架商品     | PUT /user/shop/products/{id}/offline | 是         |
| F5   | 重新上架     | PUT /user/shop/products/{id}/online  | 是         |
| F6   | 我的商品列表 | GET /user/shop/products              | 是         |
| F7   | 我的商品详情 | GET /user/shop/products/{id}         | 是         |
| F8   | 我的商品统计 | GET /user/shop/stats                 | 是         |

### 2.2 发布商品

**流程：**

1. 从 BaseContext 取 userId
2. 校验分类存在且启用
3. 遍历 imageFileIds，逐个校验归属（file.userId == userId）
4. 生成雪花 ID
5. 构造 Product：
   - sellerId = 当前用户
   - status = on_sale
   - auditStatus = approved（MVP 阶段自动通过）
   - viewCount = 0
   - favoriteCount = 0
6. 插入 product
7. 批量插入 product_image（用图片 URL）
8. 标记 file 为 used
9. 返回商品 ID

**入参：**

| 参数          | 类型       | 必填 | 约束                       |
| ------------- | ---------- | ---- | -------------------------- |
| title         | String     | 是   | 最长 100 字符              |
| description   | String     | 否   | 最长 2000 字符             |
| price         | BigDecimal | 是   | ≥ 0.01                     |
| originalPrice | BigDecimal | 否   | ≥ 0                        |
| quality       | String     | 是   | new/almost_new/good/normal |
| categoryId    | Long       | 是   | 必须存在且启用             |
| tradeType     | String     | 是   | face/express/self_pickup   |
| tradePlace    | String     | 否   | 最长 100 字符              |
| imageFileIds  | List<Long> | 是   | 1-9 个，必须是本人上传     |

**返回：** Result<Long>（商品 ID）

### 2.3 修改商品

**流程：**

1. 从 BaseContext 取 userId
2. 查商品，校验 sellerId 匹配（防越权）
3. 校验商品状态：
   - sold（已售出）→ 拒绝
   - 其他 → 允许
4. 校验分类
5. 校验新图片归属
6. 更新 product（内容变化后重置审核状态，MVP 自动 approved）
7. 删除旧图片
8. 插入新图片
9. 标记 file 为 used

**返回：** Result<Void>

### 2.4 删除商品

**流程：**

1. 从 BaseContext 取 userId
2. 查商品，校验 sellerId 匹配
3. 校验商品状态：
   - reserved（已预订）→ 拒绝
   - sold（已售出）→ 拒绝
   - 其他 → 允许
4. 逻辑删除 product（deleted = 1）
5. 物理删除 product_image

**返回：** Result<Void>

### 2.5 下架商品

**流程：**

1. 从 BaseContext 取 userId
2. 查商品，校验 sellerId 匹配
3. 校验当前状态不是 offline
4. 更新 status = offline

**返回：** Result<Void>

### 2.6 重新上架

**流程：**

1. 从 BaseContext 取 userId
2. 查商品，校验 sellerId 匹配
3. 校验当前状态不是 on_sale
4. 校验审核状态是 approved
5. 更新 status = on_sale

**返回：** Result<Void>

### 2.7 我的商品列表

**流程：**

1. 从 BaseContext 取 userId
2. 按 sellerId 查商品（包括所有状态）
3. 可选按 status 筛选
4. 关联查分类名、封面图
5. 分页返回

**入参：**

| 参数     | 类型    | 必填 | 说明     |
| -------- | ------- | ---- | -------- |
| status   | String  | 否   | 筛选状态 |
| pageNum  | Integer | 否   | 默认 1   |
| pageSize | Integer | 否   | 默认 10  |

**返回：** Result<PageResult>

### 2.8 我的商品详情

**流程：**

1. 从 BaseContext 取 userId
2. 查商品，校验 sellerId 匹配
3. 返回完整信息（含图片、分类、卖家）

**返回：** Result<ProductDetailVO>

### 2.9 我的商品统计

**流程：**

1. 从 BaseContext 取 userId
2. 聚合查询统计各状态数量和浏览收藏总数
3. 返回

**返回：** Result<UserProductStatsVO>

| 字段          | 类型    | 说明       |
| ------------- | ------- | ---------- |
| total         | Integer | 总商品数   |
| onSale        | Integer | 在售       |
| reserved      | Integer | 已预订     |
| sold          | Integer | 已售出     |
| offline       | Integer | 已下架     |
| pending       | Integer | 待审核     |
| rejected      | Integer | 审核未通过 |
| viewTotal     | Long    | 总浏览量   |
| favoriteTotal | Long    | 总收藏量   |

## 三、商品状态流转

```
发布 → on_sale（在售）
       ↓ 卖家下架
     offline（已下架）
       ↓ 卖家上架
     on_sale
       ↓ 买家申请交易
     reserved（已预订）
       ↓ 交易完成
     sold（已售出）

审核状态：
pending（待审核）→ approved（通过）/ rejected（拒绝）
```

### 状态操作矩阵

| 当前状态 | 修改 | 删除 | 下架 | 上架 |
| -------- | ---- | ---- | ---- | ---- |
| on_sale  | ✅    | ✅    | ✅    | ❌    |
| reserved | ✅    | ❌    | ✅    | ❌    |
| sold     | ❌    | ❌    | ❌    | ❌    |
| offline  | ✅    | ✅    | ❌    | ✅    |

## 四、数据库设计

**复用市集模块已建的表，不新增表。**

### 4.1 product 表

```sql
CREATE TABLE IF NOT EXISTS `product` (
    `id`             BIGINT        NOT NULL COMMENT '主键',
    `seller_id`      BIGINT        NOT NULL COMMENT '卖家ID',
    `category_id`    BIGINT        NOT NULL COMMENT '分类ID',
    `title`          VARCHAR(100)  NOT NULL COMMENT '标题',
    `description`    TEXT          COMMENT '描述',
    `price`          DECIMAL(10,2) NOT NULL COMMENT '售价',
    `original_price` DECIMAL(10,2) DEFAULT NULL COMMENT '原价',
    `quality`        VARCHAR(20)   NOT NULL DEFAULT 'good' COMMENT '成色',
    `trade_type`     VARCHAR(20)   NOT NULL DEFAULT 'face' COMMENT '交易方式',
    `trade_place`    VARCHAR(100)  DEFAULT NULL COMMENT '交易地点',
    `status`         VARCHAR(20)   NOT NULL DEFAULT 'on_sale' COMMENT '上架状态',
    `audit_status`   VARCHAR(20)   NOT NULL DEFAULT 'pending' COMMENT '审核状态',
    `audit_reason`   VARCHAR(255)  DEFAULT NULL COMMENT '审核拒绝原因',
    `view_count`     INT           NOT NULL DEFAULT 0 COMMENT '浏览量',
    `favorite_count` INT           NOT NULL DEFAULT 0 COMMENT '收藏数',
    `create_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`        TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_seller_id` (`seller_id`),
    KEY `idx_category_id` (`category_id`),
    KEY `idx_status` (`status`),
    KEY `idx_audit_status` (`audit_status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品表';
```

### 4.2 product_image 表

```sql
CREATE TABLE IF NOT EXISTS `product_image` (
    `id`          BIGINT       NOT NULL COMMENT '主键',
    `product_id`  BIGINT       NOT NULL COMMENT '商品ID',
    `url`         VARCHAR(500) NOT NULL COMMENT '图片URL',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序，0为封面',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_product_id` (`product_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品图片表';
```

### 4.3 表关系

```
user    1---N product
category 1---N product
product 1---N product_image
file    （被图片上传引用，通过 fileId 关联）
```

## 六、安全设计

### 6.1 越权防护

所有接口都涉及 `sellerId` 校验：

```
1. 从 BaseContext 取 userId
2. 查商品
3. 判断 product.sellerId == userId
   ├─ 匹配 → 继续
   └─ 不匹配 → 报错"无权操作该商品"
```

**不加会怎样：** A 用户能改 B 用户的商品。

### 6.2 图片归属校验

发布/修改商品时，`imageFileIds` 里的每个 ID 都要校验：

```
1. 查 file 表
2. 判断 file.userId == 当前 userId
   ├─ 匹配 → 继续
   └─ 不匹配 → 报错"无权使用该文件"
```

**不加会怎样：** 用户 B 冒用用户 A 上传的图片。

### 6.3 状态校验

不同操作对商品状态有不同要求：

| 操作 | 状态限制                          |
| ---- | --------------------------------- |
| 修改 | 不能是 sold                       |
| 删除 | 不能是 reserved/sold              |
| 下架 | 不能已是 offline                  |
| 上架 | 不能已是 on_sale，且必须 approved |

### 6.4 内容安全

- 标题、描述通过 `@Size` 限长
- 价格通过 `@DecimalMin` 校验
- 图片数量通过 `@Size(min=1, max=9)` 校验

### 6.5 审核机制

MVP 阶段商品发布**自动设 `audit_status = approved`**，走人工审核流程（管理端商品管理）留待后期。

**后期接入 AI 审核：**

```
发布 → auditStatus = pending
      ↓ 调用 FastAPI AI 审核
      ↓ AI 返回风险等级
      ↓ 自动通过 / 转人工 / 拒绝
```

## 十一、设计决策记录

| 决策           | 选择                    | 原因                   |
| -------------- | ----------------------- | ---------------------- |
| 图片参数       | 用 fileId，不用 URL     | 后端可校验归属，防冒用 |
| 图片更新策略   | 全删重插                | 简单，图片数量少       |
| 图片物理删除   | product_image 物理删除  | 图片表无 deleted 字段  |
| 商品逻辑删除   | product.deleted = 1     | 保留历史数据           |
| MVP 审核状态   | 自动 approved           | 简化流程，后期接入 AI  |
| 状态操作限制   | 不同状态限制不同操作    | 保证业务合理性         |
| 越权校验       | 每个接口都校验 sellerId | 防止 A 操作 B 的商品   |
| 删除已售出商品 | 拒绝                    | 订单需要引用           |
