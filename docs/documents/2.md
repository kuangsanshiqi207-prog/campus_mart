> 模块：个人中心
> 版本：V1.0

## 一、模块概述

个人中心模块负责管理用户的个人资料、密码、校园认证信息和收货地址。是用户自我管理的核心模块。

### 1.1 模块职责

| 职责         | 说明                                     |
| ------------ | ---------------------------------------- |
| 查看个人资料 | 展示当前用户的昵称、头像、邮箱、信用分等 |
| 修改个人资料 | 修改昵称、头像、邮箱                     |
| 修改密码     | 校验原密码后更新新密码，强制下线         |
| 提交校园认证 | 上传学校、学号、真实姓名、学生证图片     |
| 查看认证状态 | 查看认证审核进度和结果                   |
| 地址列表     | 展示用户所有收货地址                     |
| 新增地址     | 添加新的收货地址，可设默认               |
| 修改地址     | 修改已有地址信息                         |
| 删除地址     | 逻辑删除地址                             |

### 1.2 模块边界

**做：**

- 用户资料、密码管理
- 校园认证提交和查看（审核由管理端做）
- 收货地址增删改查

**不做：**

- 用户注册登录（属于认证模块）
- 认证审核（属于管理端用户管理模块）
- 用户封禁（属于管理端）

### 2.2 获取个人资料

**流程：**

1. 拦截器解析 token，把 userId 放入 ThreadLocal
2. 从 BaseContext 取出 userId
3. 查 user 表
4. 返回 UserVO

**返回：** Result<UserVO>

| 字段        | 类型     | 说明             |
| ----------- | -------- | ---------------- |
| id          | Long     | 用户 ID          |
| username    | String   | 用户名           |
| nickname    | String   | 昵称             |
| avatar      | String   | 头像 URL         |
| phone       | String   | 手机号           |
| email       | String   | 邮箱             |
| role        | String   | 角色             |
| status      | String   | 状态             |
| certified   | Integer  | 是否认证 0否 1是 |
| creditScore | Integer  | 信用分           |
| createTime  | DateTime | 创建时间         |

### 2.3 修改个人资料

**流程：**

1. 从 BaseContext 取 userId
2. 构造 User 对象（仅含要改的字段）
3. 更新 user 表
4. 返回成功

**入参：**

| 参数     | 类型   | 必填 | 约束                    |
| -------- | ------ | ---- | ----------------------- |
| nickname | String | 否   | 最长 50 字符            |
| avatar   | String | 否   | 最长 255 字符           |
| email    | String | 否   | 邮箱格式，最长 100 字符 |

**返回：** Result<Void>

### 2.4 修改密码

**流程：**

1. 从 BaseContext 取 userId
2. 查 user 表
3. BCrypt 校验原密码
4. 校验新密码不能与原密码相同
5. BCrypt 加密新密码
6. 更新 user 表
7. 当前 token 加入 Redis 黑名单
8. 返回成功

**入参：**

| 参数        | 类型   | 必填 | 约束      |
| ----------- | ------ | ---- | --------- |
| oldPassword | String | 是   | -         |
| newPassword | String | 是   | 6-32 字符 |

**返回：** Result<Void>

**说明：** 修改成功后，当前 token 立即失效，需要重新登录。

### 2.5 提交校园认证

**流程：**

1. 从 BaseContext 取 userId
2. 查询该用户已有的认证记录
3. 检查状态：
   - 有 pending → 报错"已有待审核的认证"
   - 有 approved → 报错"已通过校园认证"
   - 只有 rejected 或没有 → 允许继续
4. 生成雪花 ID
5. 插入 user_certification 记录，status = pending
6. 返回认证 ID

**入参：**

| 参数      | 类型   | 必填 | 约束           |
| --------- | ------ | ---- | -------------- |
| school    | String | 是   | 最长 100 字符  |
| studentNo | String | 是   | 最长 50 字符   |
| realName  | String | 是   | 最长 50 字符   |
| cardImage | String | 否   | 学生证图片 URL |

**返回：** Result<Long>（认证记录 ID）

### 2.6 查看认证状态

**流程：**

1. 从 BaseContext 取 userId
2. 查 user_certification 表，按 create_time 倒序取最新一条
3. 无记录返回 null
4. 有记录返回 CertificationVO

**返回：** Result<CertificationVO>

| 字段       | 类型     | 说明                      |
| ---------- | -------- | ------------------------- |
| id         | Long     | 认证记录 ID               |
| userId     | Long     | 用户 ID                   |
| school     | String   | 学校                      |
| studentNo  | String   | 学号                      |
| realName   | String   | 真实姓名                  |
| cardImage  | String   | 学生证图片 URL            |
| status     | String   | pending/approved/rejected |
| reason     | String   | 拒绝原因                  |
| createTime | DateTime | 提交时间                  |

### 2.7 地址列表

**流程：**

1. 从 BaseContext 取 userId
2. 查 address 表，按 is_default 降序、create_time 降序
3. 转换为 AddressVO 列表返回

**返回：** Result<List<AddressVO>>

### 2.8 新增地址

**流程：**

1. 从 BaseContext 取 userId
2. 判断 isDefault：
   - 若为 1，先清空该用户其他地址的默认标记
   - 若为 null，设为 0
3. 生成雪花 ID
4. 插入 address 记录
5. 返回地址 ID

**入参：**

| 参数      | 类型    | 必填 | 约束          |
| --------- | ------- | ---- | ------------- |
| receiver  | String  | 是   | 最长 50 字符  |
| phone     | String  | 是   | 手机号格式    |
| region    | String  | 否   | 最长 100 字符 |
| detail    | String  | 是   | 最长 255 字符 |
| isDefault | Integer | 否   | 0/1           |

**返回：** Result<Long>

### 2.9 修改地址

**流程：**

1. 从 BaseContext 取 userId
2. 查地址，判断是否存在
3. 校验 user_id 是否匹配（防越权）
4. 若 isDefault 为 1，先清空其他默认
5. 更新 address 表
6. 返回成功

**返回：** Result<Void>

### 2.10 删除地址

**流程：**

1. 从 BaseContext 取 userId
2. 查地址，判断是否存在
3. 校验 user_id 是否匹配（防越权）
4. 逻辑删除（deleted = 1）
5. 返回成功

**返回：** Result<Void>

## 三、数据库设计

### 3.1 user 表

复用认证模块的 user 表，**不新增字段**。

涉及字段：

| 字段         | 用途                         |
| ------------ | ---------------------------- |
| nickname     | 个人资料                     |
| avatar       | 个人资料                     |
| email        | 个人资料                     |
| password     | 修改密码                     |
| certified    | 认证状态（管理端审核后更新） |
| credit_score | 信用分                       |

### 3.2 user_certification 表

```sql
CREATE TABLE IF NOT EXISTS `user_certification` (
    `id`           BIGINT       NOT NULL COMMENT '主键',
    `user_id`      BIGINT       NOT NULL COMMENT '用户ID',
    `school`       VARCHAR(100) NOT NULL COMMENT '学校',
    `student_no`   VARCHAR(50)  NOT NULL COMMENT '学号',
    `real_name`    VARCHAR(50)  NOT NULL COMMENT '真实姓名',
    `card_image`   VARCHAR(500) DEFAULT NULL COMMENT '学生证图片URL',
    `status`       VARCHAR(20)  NOT NULL DEFAULT 'pending' COMMENT 'pending/approved/rejected',
    `reason`       VARCHAR(255) DEFAULT NULL COMMENT '审核拒绝原因',
    `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`      TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_status` (`status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '校园认证表';
```

**字段说明：**

| 字段       | 说明               | 约束                      |
| ---------- | ------------------ | ------------------------- |
| id         | 主键，雪花算法生成 | 唯一                      |
| user_id    | 用户 ID            | 关联 user.id              |
| school     | 学校名称           | 非空                      |
| student_no | 学号               | 非空                      |
| real_name  | 真实姓名           | 非空                      |
| card_image | 学生证图片 URL     | 可空                      |
| status     | 审核状态           | pending/approved/rejected |
| reason     | 拒绝原因           | 仅 rejected 时有值        |
| deleted    | 逻辑删除           | 默认 0                    |

### 3.3 address 表

```sql
CREATE TABLE IF NOT EXISTS `address` (
    `id`           BIGINT       NOT NULL COMMENT '主键',
    `user_id`      BIGINT       NOT NULL COMMENT '用户ID',
    `receiver`     VARCHAR(50)  NOT NULL COMMENT '收货人',
    `phone`        VARCHAR(20)  NOT NULL COMMENT '手机号',
    `region`       VARCHAR(100) DEFAULT NULL COMMENT '地区',
    `detail`       VARCHAR(255) NOT NULL COMMENT '详细地址',
    `is_default`   TINYINT      NOT NULL DEFAULT 0 COMMENT '是否默认 0否 1是',
    `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`      TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '收货地址表';
```

**字段说明：**

| 字段       | 说明               | 约束         |
| ---------- | ------------------ | ------------ |
| id         | 主键，雪花算法生成 | 唯一         |
| user_id    | 用户 ID            | 关联 user.id |
| receiver   | 收货人             | 非空         |
| phone      | 手机号             | 非空         |
| region     | 地区               | 可空         |
| detail     | 详细地址           | 非空         |
| is_default | 是否默认           | 0/1          |
| deleted    | 逻辑删除           | 默认 0       |

### 3.4 表关系

```
user
 ├── 1:N → user_certification   （一个用户多次提交认证）
 └── 1:N → address               （一个用户多个地址）
```

## 四、Redis 设计

### 4.1 Key 列表

| Key                            | 类型   | TTL              | 用途                 |
| ------------------------------ | ------ | ---------------- | -------------------- |
| campus:token:blacklist:{token} | String | token 剩余有效期 | 修改密码后加入黑名单 |

### 4.2 Token 黑名单

```
key:   campus:token:blacklist:eyJhbGciOiJIUzI1NiJ9...
value: "1"
TTL:   token 剩余有效期
```

**触发时机：**

- 认证模块：用户主动登出
- 个人中心：用户修改密码后

**为什么修改密码要加黑名单：**

修改密码后，原 token 仍然有效。如果不加黑名单，攻击者拿到旧 token 还能继续使用。加入黑名单后，原 token 立即失效，用户需要用新密码重新登录。

## 五、安全设计

### 5.1 越权防护

所有涉及资源 ID 的接口（地址、认证）都必须校验**资源归属**：

```
1. 从 BaseContext 取 userId
2. 查资源
3. 判断 resource.userId == userId
   ├─ 匹配 → 继续
   └─ 不匹配 → 报错"无权操作"
```

**不加会怎样：**

用户 A 拿到用户 B 的地址 ID，就能修改或删除 B 的地址。

### 5.2 密码安全

- 校验原密码后才能修改
- 新密码不能与原密码相同
- 新密码 BCrypt 加密
- 修改后强制下线

### 5.3 认证归属

查询认证记录时，只查当前用户自己的：

```sql
SELECT * FROM user_certification
WHERE user_id = #{userId} AND deleted = 0
```

### 5.4 地址归属

修改/删除地址前，必须校验 `address.user_id == 当前 userId`。

## 十、设计决策记录

| 决策         | 选择                      | 原因                 |
| ------------ | ------------------------- | -------------------- |
| 个人资料存储 | 复用 user 表              | 一对一，无需拆表     |
| 认证存储     | 独立表 user_certification | 一对多，有审核流程   |
| 地址存储     | 独立表 address            | 一对多，可被订单引用 |
| ID 生成      | Hutool 雪花算法           | 全局唯一，趋势递增   |
| 密码修改后   | 加入黑名单强制下线        | 安全性考虑           |
| 认证重复提交 | pending/approved 时禁止   | 防止重复审核         |
| 地址默认     | 数据库层清空其他默认      | 保证唯一             |
| 越权防护     | 每个接口校验 userId       | 防止 A 操作 B 的资源 |
| Mapper 实现  | XML 形式                  | 便于维护复杂 SQL     |
