## 一、模块概述

用户管理模块是管理端的核心监管模块，负责用户信息查询、封禁解封、信用分调整和校园认证审核。

### 1.1 模块职责

| 职责         | 说明                       |
| ------------ | -------------------------- |
| 用户列表     | 查询、搜索、筛选用户       |
| 用户详情     | 查看用户完整信息和认证状态 |
| 封禁/解封    | 修改用户账号状态           |
| 信用分调整   | 手动增减用户信用分         |
| 认证审核列表 | 查看待审核的校园认证       |
| 认证审核     | 通过/拒绝校园认证          |

### 1.2 模块边界

**做：**

- 用户数据查询
- 用户状态和信用分的修改
- 校园认证审核

**不做：**

- 用户注册（属于用户端认证模块）
- 用户资料修改（属于用户端个人中心）
- 用户删除（MVP 阶段不提供）

### 1.3 与用户端的关系

| 数据         | 用户端     | 管理端    |
| ------------ | ---------- | --------- |
| 用户基本信息 | 只读自己的 | 读全部    |
| 认证提交     | 提交       | 审核      |
| 信用分       | 查看自己   | 调整      |
| 账号状态     | 无权限     | 封禁/解封 |

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能         | 接口                           | 是否需登录 |
| ---- | ------------ | ------------------------------ | ---------- |
| F1   | 用户列表     | GET /admin/users               | 是         |
| F2   | 用户详情     | GET /admin/users/{id}          | 是         |
| F3   | 封禁/解封    | PUT /admin/users/{id}/status   | 是         |
| F4   | 调整信用分   | PUT /admin/users/{id}/credit   | 是         |
| F5   | 认证审核列表 | GET /admin/certifications      | 是         |
| F6   | 审核认证     | PUT /admin/certifications/{id} | 是         |

### 2.2 用户列表

**流程：**

1. 接收查询条件（keyword、status、certified、分页）
2. 组装 SQL 条件：
   - keyword：模糊匹配 username / nickname / phone
   - status：按状态筛选
   - certified：按认证状态筛选
3. 分页查询 user 表
4. 转 UserVO
5. 返回 PageResult

**入参：**

| 参数      | 类型    | 必填 | 说明              |
| --------- | ------- | ---- | ----------------- |
| keyword   | String  | 否   | 关键词            |
| status    | String  | 否   | normal/banned     |
| certified | Integer | 否   | 0未认证 / 1已认证 |
| pageNum   | Integer | 否   | 默认 1            |
| pageSize  | Integer | 否   | 默认 10           |

**返回：** Result<PageResult<UserVO>>

### 2.3 用户详情

**流程：**

1. 校验用户存在
2. 查用户基本信息
3. 查该用户的认证记录（最新一条）
4. 组装 UserDetailVO（含 user + certification）
5. 返回

**返回：** Result<UserDetailVO>

| 字段          | 类型            | 说明                  |
| ------------- | --------------- | --------------------- |
| user          | UserVO          | 用户基本信息          |
| certification | CertificationVO | 认证信息，可能为 null |

### 2.4 封禁/解封

**流程：**

1. 校验用户存在
2. 校验 status 是 normal 或 banned
3. 更新 user.status
4. 发站内信通知用户
5. 返回

**入参：**

| 参数   | 类型   | 必填 | 约束          |
| ------ | ------ | ---- | ------------- |
| status | String | 是   | normal/banned |
| reason | String | 否   | 封禁原因      |

**返回：** Result<Void>

**后续优化：** 用户被 ban 后，拦截器应校验用户状态，拒绝请求。MVP 阶段先不实现，后期加 Redis 缓存。

### 2.5 调整信用分

**流程：**

1. 校验用户存在
2. 计算新分数：`newScore = max(0, oldScore + delta)`
3. 更新 user.credit_score
4. 写 credit_log 流水：
   - delta：变动值
   - before_score：变动前
   - after_score：变动后
   - reason：变动原因
   - biz_type：admin
   - biz_id：当前管理员 ID
5. 发站内信通知用户
6. 返回

**入参：**

| 参数   | 类型    | 必填 | 说明               |
| ------ | ------- | ---- | ------------------ |
| delta  | Integer | 是   | 正数加分，负数扣分 |
| reason | String  | 是   | 变动原因           |

**返回：** Result<Void>

**为什么要写流水：** 用户端的"信用分流水"接口会展示这些记录。

### 2.6 认证审核列表

**流程：**

1. 按 status 筛选（不传则查全部）
2. 按创建时间正序（先到先审）
3. 分页查询 user_certification
4. 转 CertificationVO
5. 返回

**入参：**

| 参数     | 类型    | 必填 | 说明                      |
| -------- | ------- | ---- | ------------------------- |
| status   | String  | 否   | pending/approved/rejected |
| pageNum  | Integer | 否   | 默认 1                    |
| pageSize | Integer | 否   | 默认 10                   |

**返回：** Result<PageResult<CertificationVO>>

### 2.7 审核认证

**流程：**

1. 校验认证记录存在
2. 校验当前状态是 pending（防止重复审核）
3. 校验审核结果合法（approved/rejected）
4. 更新 user_certification 的 status、reason
5. 如果 approved：
   - 更新 user.certified = 1
6. 发站内信通知用户
7. 返回

**入参：**

| 参数   | 类型   | 必填 | 说明              |
| ------ | ------ | ---- | ----------------- |
| status | String | 是   | approved/rejected |
| reason | String | 否   | 拒绝原因          |

**返回：** Result<Void>

## 四、安全设计

### 4.1 拦截器

管理端拦截器 `/admin/**` 校验：

- token 有效性
- type = admin
- 不在黑名单

### 4.2 操作权限

MVP 阶段，所有管理员都能操作用户管理功能。

**后续优化：** 按角色细分：

| 角色        | 权限                         |
| ----------- | ---------------------------- |
| SUPER_ADMIN | 全部                         |
| ADMIN       | 用户管理、商品管理、订单管理 |
| AUDITOR     | 只能审核认证、商品           |
| OPERATOR    | 只能查看，不能修改           |

### 4.3 关键操作留痕

| 操作       | 留痕                      |
| ---------- | ------------------------- |
| 封禁/解封  | 站内信通知用户            |
| 调整信用分 | 写 credit_log 流水        |
| 审核认证   | 更新 certification.status |

**后续优化：** 加管理员操作日志表，记录每次管理操作的 IP、时间、目标。

### 4.4 防止误操作

| 保护       | 说明                       |
| ---------- | -------------------------- |
| 重复审核   | 校验 status 必须是 pending |
| 重复封禁   | 允许（幂等）               |
| 信用分下限 | max(0, ...) 防止负数       |

## 九、设计决策记录

| 决策         | 选择               | 原因                   |
| ------------ | ------------------ | ---------------------- |
| 用户删除     | 不提供             | 保留历史数据，避免误删 |
| 封禁实现     | 修改 status 字段   | 简单直接               |
| 信用分下限   | max(0, ...)        | 防止负数               |
| 信用流水     | 每次调整都写       | 用户端可查看           |
| 认证审核     | 只能审核一次       | 防止重复审核           |
| 通知机制     | 复用 MessageSender | 解耦，统一消息入口     |
| 用户状态校验 | MVP 暂不加         | 后期 Redis 缓存优化    |
