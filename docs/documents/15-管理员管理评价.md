## 一、模块概述

评价管理模块是管理端的监管模块，负责全平台评价的查询和违规评价的删除。管理员可以介入违规评价，保证平台内容合规。

### 1.1 模块职责

| 职责         | 说明                                 |
| ------------ | ------------------------------------ |
| 评价列表     | 查询全平台评价，支持关键词、评分筛选 |
| 删除违规评价 | 逻辑删除评价，通知评价人             |

### 1.2 模块边界

**做：**

- 全平台评价数据查询
- 违规评价逻辑删除

**不做：**

- 评价的创建、回复（属于用户端评价模块）
- 信用分联动（属于个人统计模块）
- 评价统计（属于统计模块）

### 1.3 与用户端评价模块的关系

| 数据     | 用户端评价模块        | 管理端评价管理    |
| -------- | --------------------- | ----------------- |
| 评价列表 | 只看自己发出的/收到的 | 看全平台          |
| 评价详情 | 商品评价、评价详情    | 全平台            |
| 删除     | MVP 不做              | 管理员可删除违规  |
| 路径     | /user/reviews/**      | /admin/reviews/** |
| 权限     | 登录用户 / 公开       | 管理员            |

## 二、功能设计

### 2.1 功能清单

| 编号 | 功能         | 接口                       | 是否需登录 |
| ---- | ------------ | -------------------------- | ---------- |
| F1   | 评价列表     | GET /admin/reviews         | 是         |
| F2   | 删除违规评价 | DELETE /admin/reviews/{id} | 是         |

### 2.2 评价列表

**流程：**

1. 接收查询条件（keyword、score、分页）
2. 组装 SQL 条件：
   - keyword：模糊匹配 content
   - score：按评分筛选
3. 分页查询 review 表（deleted = 0）
4. 关联查评价人昵称
5. 转 ReviewVO
6. 返回 PageResult

**入参：**

| 参数     | 类型    | 必填 | 说明             |
| -------- | ------- | ---- | ---------------- |
| keyword  | String  | 否   | 关键词，匹配内容 |
| score    | Integer | 否   | 评分 1-5         |
| pageNum  | Integer | 否   | 默认 1           |
| pageSize | Integer | 否   | 默认 10          |

**返回：** Result<PageResult<ReviewVO>>

| 字段             | 类型         | 说明       |
| ---------------- | ------------ | ---------- |
| id               | Long         | 评价ID     |
| orderId          | Long         | 订单ID     |
| productId        | Long         | 商品ID     |
| fromUserId       | Long         | 评价人ID   |
| fromUserNickname | String       | 评价人昵称 |
| toUserId         | Long         | 被评价人ID |
| score            | Integer      | 评分       |
| content          | String       | 评价内容   |
| images           | List<String> | 图片URL    |
| reply            | String       | 回复       |
| createTime       | DateTime     | 创建时间   |

### 2.3 删除违规评价

**流程：**

1. 查评价，不存在报错
2. 逻辑删除 review（deleted = 1）
3. 发站内信通知评价人
4. 返回

**返回：** Result<Void>

**说明：** 评价删除是逻辑删除，保留数据用于审计。不做信用分联动（信用分调整由管理端用户管理手动执行）。

## 三、数据库设计

**复用评价模块已建的 review 表，不新增表。**

### 3.1 review 表

```sql
CREATE TABLE IF NOT EXISTS `review` (
    `id`             BIGINT        NOT NULL COMMENT '主键',
    `order_id`       BIGINT        NOT NULL COMMENT '订单ID',
    `product_id`     BIGINT        NOT NULL COMMENT '商品ID',
    `from_user_id`   BIGINT        NOT NULL COMMENT '评价人ID',
    `to_user_id`     BIGINT        NOT NULL COMMENT '被评价人ID',
    `score`          TINYINT       NOT NULL COMMENT '评分 1-5',
    `content`        VARCHAR(500)  DEFAULT NULL COMMENT '评价内容',
    `images`         VARCHAR(2000) DEFAULT NULL COMMENT '图片URL列表，逗号分隔',
    `reply`          VARCHAR(500)  DEFAULT NULL COMMENT '被评价人的回复',
    `reply_time`     DATETIME      DEFAULT NULL COMMENT '回复时间',
    `create_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`        TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_order_from` (`order_id`, `from_user_id`),
    KEY `idx_product_id` (`product_id`),
    KEY `idx_to_user_id` (`to_user_id`),
    KEY `idx_from_user_id` (`from_user_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '评价表';
```

### 3.2 关键索引

| 索引               | 用途         |
| ------------------ | ------------ |
| `uk_order_from`    | 一单一评     |
| `idx_product_id`   | 商品评价列表 |
| `idx_to_user_id`   | 我收到的评价 |
| `idx_from_user_id` | 我发出的评价 |

## 五、安全设计

### 5.1 权限隔离

管理端接口在 `/admin/reviews/**` 下：

- 用户 token 不能访问（type 校验）
- 只有管理员 token 能访问

### 5.2 操作权限

MVP 阶段，所有管理员都能操作评价管理功能。

### 5.3 关键操作留痕

| 操作     | 留痕                         |
| -------- | ---------------------------- |
| 删除评价 | 逻辑删除，发站内信通知评价人 |

### 5.4 防止误操作

| 保护     | 说明           |
| -------- | -------------- |
| 逻辑删除 | 保留数据可追溯 |

## 十、设计决策记录

| 决策           | 选择               | 原因               |
| -------------- | ------------------ | ------------------ |
| 复用 review 表 | 不新增表           | 数据结构一致       |
| 评价删除       | 逻辑删除           | 保留数据用于审计   |
| 评价人昵称     | 列表里 join 查询   | 管理端需要看到     |
| 通知机制       | 复用 MessageSender | 解耦，统一消息入口 |
| 信用分联动     | 不做               | 由用户管理手动执行 |
| 权限           | MVP 不细分角色     | 后期按角色控制     |
